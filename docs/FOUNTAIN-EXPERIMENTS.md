# Проверки и эксперименты фонтанных кодов

Алгебраические тесты проверяют правильность кодирования, декодирования,
локального ремонта, протокола и ограничений. Статистические эксперименты
отдельно измеряют, как часто случайный набор частей позволяет восстановление.

## Тесты и независимые эталоны

Из корня workspace:

```sh
cargo test -p gf-linalg -p fountain-codes
cargo test --workspace --release
cargo +1.81.0 test -p fountain-codes
python3 tools/fountain_spec_vectors.py --check
node tools/check_fountain_spec.mjs
```

Python и JavaScript независимо вычисляют контрольные значения
[профиля v1](FOUNTAIN-SPEC-V1.md). Оба скрипта обходятся стандартными
библиотеками. JSON содержит ожидаемые результаты и не перезаписывается при
обычных проверках.

## Один эксперимент

[Пример experiment](../fountain-codes/examples/experiment.rs) выводит CSV в
stdout, параметры и сводку — в stderr. Параметры ниже экспериментальные.

```sh
cargo run --release -p fountain-codes --example experiment -- \
  --profile gf256 --k 100 --epsilon 0.1 --mode sample \
  --instances 1 --trials 1 --seed 42 \
  --max-observations 1 --max-work 1000000000 --time-budget-seconds 60
```

В режиме sample выбираются M=ceil((1+epsilon)*K) разных частей из первых 2K.
Параметр epsilon обрабатывается как точное десятичное число: при K=100 и
epsilon=0.1 получаем M=110. Поддерживается научная запись, например 1e-1.
Регрессионные тесты проверяют границы округления и неверные параметры.

Режим loss вместо фиксированного M стирает каждую часть независимо с
вероятностью --loss. Полное восстановление проверяется по исходным байтам;
нехватка ранга является допустимым результатом эксперимента.

Локальный сценарий отдельно удаляет случайную исходную или проверочную часть.
Остальные части доступны с вероятностью 1-repair_loss. Исполнитель ремонта
получает только доступные части через callback; потерянная цель ему недоступна.
Ожидаемый результат знает только проверяющий код эксперимента.

## Ограниченная сетка

[Скрипт запуска](../tools/run_fountain_experiments.py) сохраняет параметры,
версию компилятора, хеши исходников, CSV, журналы и сводку по каждому code
instance. Выходной каталог должен быть новым или пустым.

```sh
python3 tools/run_fountain_experiments.py --output /tmp/fountain-smoke
```

По умолчанию используются два поля, K=12, c=4, seed=42, две модели потерь,
2 code instances и 3 trials на instance: всего 24 наблюдения. Скрипт требует
установленных Rust/Cargo и доступных зависимостей в офлайн-кэше. Флаги
--max-observations, --max-work и --time-budget-seconds ограничивают объём
работы; --paper выбирает K=100/300/500 и c=4/6 и требует подходящих бюджетов.

## Сохранённый проверочный запуск

[Параметры и сводка](experiments/fountain-smoke/summary.json) и четыре CSV
содержат записанный запуск от 2026-10-19 после исправления округления.
Это выборка сохранённых данных, а не новый запуск при подготовке PR.

| Поле | Режим | Полное восстановление | Успешный локальный ремонт |
|---|---|---:|---:|
| GF(256) | sample | 6/6 | 5/6 |
| GF(256) | loss | 6/6 | 3/6 |
| GF(65536) | sample | 6/6 | 5/6 |
| GF(65536) | loss | 6/6 | 3/6 |

Исходные CSV: [GF(256), sample](experiments/fountain-smoke/gf256-k12-c4-sample.csv),
[GF(256), loss](experiments/fountain-smoke/gf256-k12-c4-loss.csv),
[GF(65536), sample](experiments/fountain-smoke/gf65536-k12-c4-sample.csv),
[GF(65536), loss](experiments/fountain-smoke/gf65536-k12-c4-loss.csv).

Такой объём подтверждает работу инструмента и точность найденных
восстановлений. Он не оценивает надёжность всего семейства и не воспроизводит
большую статистическую сетку статьи. Trials одного instance коррелированы;
доверительные интервалы не заявляются. Время зависит от машины, расчёт памяти
соответствует логическому бюджету v1 и не измеряет RSS.

Условие q>K само по себе не даёт гарантию теоремы 1 статьи: требуется также
достаточная константа c. Значения c=4/6 и epsilon=0.1 используются для
эмпирического сравнения. Фиксированный SplitMix64 не является доказательством
свойств идеального случайного ансамбля.
