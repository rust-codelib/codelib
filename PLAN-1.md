# Этап 1: основа крейта `ldpc-codes`

**Статус:** план для обсуждения и последующей реализации. Описанных функций LDPC в репозитории пока нет.

Основание: этап 1 из [GENERAL-PLAN.md](GENERAL-PLAN.md) и требования [Codelib.md](Codelib.md). Документ совмещает спецификацию интерфейсов и список задач; отдельные `SPEC.md` и `tasks/todo.md` для этого этапа не создаются.

## 1. Результат этапа и границы

После реализации пользователь сможет создать проверочную матрицу из списков позиций единиц, вычислить синдром слова и преобразовать последовательность битов в `Vector<Gf2>` и обратно.

Также здесь фиксируются контракты будущих кодера, декодера, конфигуратора и логирования. Их реализации относятся к этапам 2–4: на этапе 1 они описаны в документации, а не представлены функциями с `todo!()` или результатом «не реализовано».

На этом этапе не выполняются вычисление ранга, подготовка кодера, SPA, подсчёт исправленных ошибок, упаковка байтов сообщения или создание полинома. Общий полином будет связан с `Vector<F>` после появления своего крейта и API, как предусмотрено этапом 6.

RREF и обобщённые `Matrix<F>` и `Vector<F>` уже реализованы в `gf-linalg`. Подготовка этого плана не требует RREF: функции этапа 1 используют существующий векторный API и GF(2). Для кодера на этапе 2 RREF остаётся технической зависимостью.

## 3. API, реализуемый на этапе 1

### 3.1. Бит и преобразования вектора

Предлагаемый публичный API:

```rust
pub enum Bit { Zero, One }
pub type Gf2 = gfpm::Gf<2, 1, 1>;

// Для Bit: Copy, Clone, Debug, PartialEq, Eq.
// Также: TryFrom<u8, Error = LdpcError> и From<Bit> for u8.

pub fn bits_to_vector(bits: &[Bit]) -> gf_linalg::Vector<Gf2>;
pub fn vector_to_bits(
    vector: &gf_linalg::Vector<Gf2>,
) -> Result<Vec<Bit>, LdpcError>;
```

`Bit::try_from(0)` и `Bit::try_from(1)` успешны; остальные значения возвращают ошибку. Тип бита не позволяет хранить третье состояние.

`bits_to_vector` отображает Zero в `Gf2::zero()`, One в `Gf2::one()`. Обратное преобразование проверяет именно эти два значения; произвольное значение поля нельзя молча считать единицей. Хотя корректный `Gf2` состоит только из 0 и 1, проверка защищает границу преобразования от неканонического элемента, созданного с нарушением контракта `gfpm`.

Пустой ввод, длина, порядок и нулевые элементы в конце сохраняются. Функции заимствуют источник — принимают ссылку и оставляют данные доступными вызывающему коду — и возвращают отдельные коллекции.

Здесь нет проверки длины относительно конкретного кода: длину `k` позже проверяет кодер. Существующие `Vector::try_to_polynomial_coefficients` и `Vector::from_polynomial_coefficients` уже работают с массивами коэффициентов; новый тип полинома ими не подменяется.

### 3.2. Проверочная матрица

```rust
impl ParityCheckMatrix {
    pub fn try_from_rows(
        bits: usize,
        rows: Vec<Vec<usize>>,
    ) -> Result<Self, LdpcError>;

    pub fn rows(&self) -> usize;
    pub fn cols(&self) -> usize;
    pub fn edge_count(&self) -> usize;
    pub fn check_bits(&self, check: usize) -> Option<&[usize]>;
    pub fn bit_checks(&self, bit: usize) -> Option<&[usize]>;

    pub fn syndrome(&self, word: &[Bit]) -> Result<Vec<Bit>, LdpcError>;
    pub fn is_codeword(&self, word: &[Bit]) -> Result<bool, LdpcError>;
}
```

`bits` — число столбцов `n`. Число строк `m` определяется длиной внешнего `rows`. Например, `try_from_rows(3, vec![vec![0, 2], vec![1, 2]])` задаёт:

```text
1 0 1
0 1 1
```

Правила конструктора:

- `1 <= m, n <= gf_linalg::MAX_MATRIX_DIM` — сейчас максимум 4096 по каждой оси;
- каждый индекс бита меньше `n`; повтор индекса в одной строке запрещён;
- индексы строки сортируются по возрастанию; вход `[2, 0]` эквивалентен `[0, 2]`;
- пустые строки, одинаковые строки и столбцы без единиц допустимы;
- нулевая матрица допустима: наличие формы не требует наличия рёбер;
- внешние данные принимаются во владение; форма и смежности после создания закрыты от изменения.

Сначала проверить форму, затем обойти строки по порядку. В каждой строке сначала проверить индексы в порядке ввода, затем отсортировать и проверить повторы. Только после успешной проверки построить обратные связи. Некорректный ввод не должен возвращать частично построенный объект.

Для начала достаточно списков `check → bits` и `bit → checks` вместе с числом столбцов и общим числом рёбер. Обратные списки проверок тоже упорядочены. Хранение занимает `O(m + n + E)`, где `E` — число единиц; плотный буфер `m * n` не выделяется. Число рёбер и размеры буферов считаются с проверкой переполнения. Публичный тип номера ребра пока не нужен: в SPA внутренние индексы сообщений будут построены по этому графу.

`check_bits` и `bit_checks` возвращают `None` за границей и `Some(&[])` для существующего узла без соседей. `Option` обозначает наличие или отсутствие результата; пустой список и отсутствующий узел различаются.

### 3.3. Синдром

Перед вычислением проверить `word.len() == n`. Каждый элемент синдрома — XOR битов одной проверки; результат имеет длину `m` в исходном порядке строк. Пустая проверка даёт Zero.

`is_codeword` возвращает true, если все проверки равны Zero. Неверная длина — ошибка, а не false. Матрица и слово остаются неизменными.

Для матрицы из примера:

```text
word = [1, 1, 1] → syndrome = [0, 0], is_codeword = true
word = [1, 0, 0] → syndrome = [1, 0], is_codeword = false
```

Нулевой синдром подтверждает принадлежность слова к коду, но не означает, что слово было передано без ошибки.

### 3.4. Ошибки этапа 1

`LdpcError` реализует `Debug`, `PartialEq`, `Eq`, `Display` и `std::error::Error`. Диагностика содержит размеры или индексы, по которым можно найти неверные входные данные.

| Вариант | Поля | Условие |
| --- | --- | --- |
| `InvalidBit` | `value: u8` | Значение при преобразовании в Bit не равно 0 или 1 |
| `InvalidFieldElement` | `index: usize, value: u64` | Коэффициент вектора не равен нулю или единице GF(2) |
| `InvalidDimensions` | `rows: usize, cols: usize` | Нулевая или превышающая лимит ось |
| `BitIndexOutOfBounds` | `check: usize, bit: usize, bits: usize` | Индекс бита в строке вне формы |
| `DuplicateBitIndex` | `check: usize, bit: usize` | В одной проверке бит указан дважды |
| `WordLengthMismatch` | `expected: usize, actual: usize` | Длина слова не равна числу столбцов |
| `SizeOverflow` | — | Переполнение расчёта размера внутреннего хранилища |

Ошибки возвращаются через `Result`: `Ok(...)` содержит результат, `Err(...)` — причину отказа. `unwrap` и паники из-за пользовательского ввода в библиотечных методах не допускаются. Тесты сравнивают варианты и поля ошибок, не зависят от полного текста Display.

## 4. Контракты следующих этапов

Этот раздел фиксирует направление публичного API, но не создаёт на этапе 1 неработающие экспортируемые типы. Реальные объявления появляются вместе с рабочими реализациями на этапах 2–4. Изменение этих контрактов сначала отражается в плане.

### 4.1. Кодер, декодер и конфигуратор

```rust
pub trait Encoder {
    fn message_len(&self) -> usize;
    fn codeword_len(&self) -> usize;
    fn encode(&self, message: &[Bit]) -> Result<Vec<Bit>, LdpcError>;
    fn extract_message(&self, word: &[Bit]) -> Result<Vec<Bit>, LdpcError>;
}

pub struct DecodeInput<'a> {
    pub llrs: &'a [f64],
    pub erasures: &'a [usize],
}

pub trait Decoder {
    fn codeword_len(&self) -> usize;
    fn decode(
        &mut self,
        input: DecodeInput<'_>,
        observer: Option<&mut dyn DecodeObserver>,
    ) -> Result<DecodeResult, LdpcError>;
}

impl LdpcConfigurator {
    pub fn build(
        checks: ParityCheckMatrix,
        config: DecoderConfig,
    ) -> Result<ConfiguredLdpc, LdpcError>;
}
```

`Encoder` реализует `SystematicEncoder`, `Decoder` — `SpaDecoder`. `&mut self` позволяет декодеру повторно использовать рабочие буферы; перед каждым блоком состояние сообщений сбрасывается. Временная ссылка в `DecodeInput<'a>` означает, что входные массивы используются во время вызова и не сохраняются в результате.

Кодер проверяет ровно `k` битов сообщения, работает через `Vector<Gf2>` и возвращает `n` битов в исходном порядке `H`. `extract_message` проверяет длину и нулевой синдром, затем использует сохранённые информационные позиции. Это извлечение из допустимого слова, а не гарантия верности сообщения.

`DecoderConfig` хранит `max_iterations` и `llr_limit` с проверяемым конструктором `try_new(max_iterations: usize, llr_limit: f64) -> Result<Self, LdpcError>`. В первой версии конфигурация относится к SPA. Безопасный численный диапазон и значения по умолчанию фиксируются в `PLAN-3.md` перед реализацией; бюджет 0 допустим.

`ConfiguredLdpc` хранит согласованные кодер и декодер с доступом через `encoder()` и `decode(input, observer)`. Прямой доступ к внутреннему декодеру не предоставляется, чтобы нельзя было заменить его декодером для другой `H`. Конфигуратор сам получает размеры, ранг и информационные позиции из `H`; пользователь не задаёт отдельно `k`. Доступ к изменению `H` после сборки не предоставляется.

Получатель логирования передаётся в `decode`, а не хранится в конфигурации: это позволяет подключать журнал для конкретного вызова без управления временем жизни внешнего получателя. `None` отключает события. Файл и stdout принадлежат вызывающему приложению.

Входной LLR определяется как `ln(P(0)/P(1))`. Нулевой LLR даёт жёсткое решение Zero. Позиции стираний относятся к исходному порядку `H` и устанавливают соответствующие LLR в 0; неверные индексы и повторы — ошибки. Диагностическое начальное решение определяется после подготовки канального входа, включая стирания.

### 4.2. Результат и события

`DecodeResult` — неизменяемый результат с закрытыми полями и читающими методами:

| Метод | Тип | Значение |
| --- | --- | --- |
| `word()` | `&[Bit]` | Последнее решение длины `n` |
| `posterior_llrs()` | `&[f64]` | Итоговые LLR длины `n` |
| `syndrome()` | `&[Bit]` | Итоговый синдром длины `m` |
| `status()` | `DecodeStatus` | `ParitySatisfied` либо `IterationLimit` |
| `iterations()` | `usize` | Число полностью выполненных итераций |
| `changed_bits()` | `usize` | Различия итогового слова и начального жёсткого решения |
| `initial_unsatisfied_checks()` | `usize` | Число невыполненных начальных проверок |
| `final_unsatisfied_checks()` | `usize` | Число невыполненных итоговых проверок |

Для внешней реализации `Decoder` доступен проверяемый конструктор:

```rust
pub fn try_new(
    checks: &ParityCheckMatrix,
    initial_word: &[Bit],
    posterior_llrs: Vec<f64>,
    status: DecodeStatus,
    iterations: usize,
    iteration_limit: usize,
) -> Result<DecodeResult, LdpcError>;
```

Итоговое слово выводится из знаков конечных `posterior_llrs`; синдром и
счётчики вычисляются по `checks` и `initial_word`. Конструктор проверяет длины,
конечность LLR, `iterations <= iteration_limit` и согласованность статуса:
`ParitySatisfied` требует нулевой синдром, а `IterationLimit` — ненулевой
синдром и исчерпанный бюджет. При `iterations == 0` итоговое жёсткое слово
должно совпадать с `initial_word`. Исходное начальное решение и факт выполнения
заявленного числа итераций остаются ответственностью внешнего алгоритма:
результат не хранит и не проверяет историю его вычислений.

`ParitySatisfied` означает нулевой синдром. `IterationLimit` — допустимый исход, при котором нельзя автоматически выдавать последнее слово как восстановленное сообщение. Настоящее число ошибок подсчитывается отдельно сравнением с эталоном; оно не равно `changed_bits` или числу невыполненных проверок.

Интерфейс получателя: `DecodeObserver::on_event(&mut self, event: &DecodeEvent)`. Варианты события: `Started`, `IterationFinished` и `Finished`. Они сообщают номер итерации, число невыполненных проверок; итоговое событие также сообщает статус и `changed_bits`. Полные массивы сообщений не копируются в журнал по умолчанию.

Порядок при успешном входе: одно Started, затем по одному IterationFinished на завершённую итерацию, затем одно Finished. При остановке на исходном решении итерационных событий нет. Неверный ввод возвращает ошибку до Started. Ссылка на событие действует только во время callback; для хранения приложение копирует нужные сведения. Ошибка записи журнала обрабатывается самим получателем и не становится ошибкой декодирования.

## 6. Проверки и завершение

После каждой небольшой задачи — `cargo test -p ldpc-codes`. По завершении этапа:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test --workspace --release
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps
cargo +1.81.0 check --workspace --lib
```

Новый member автоматически включается в workspace CI. Embedded-задача остаётся для `gf2m`, `gfpm`, `rs-codes`: она уже перечисляет эти пакеты явно. Границы матрицы берутся из `MAX_MATRIX_DIM`; ограничения 128 КиБ для будущего полинома и 4096 байт целого сообщения здесь не накладываются на произвольный `Vector<Gf2>`.
