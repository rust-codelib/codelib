# codelib-testkit

Минимальный консольный стенд: smoke-проверки публичных API всех пяти крейтов,
TOML-конфигурация, логи, скорости кодирования/декодирования и подсчёт ошибок.

Запуск из корня workspace (Rust 1.81+):

```sh
cargo run --locked --release -p codelib-testkit -- --config configs/smoke.toml
```

Без аргументов используется `configs/smoke.toml`. `--help` выводит справку.
Результаты идут в stdout, логи — в stderr; `RUST_LOG` переопределяет `log_level`.
Ограничений на скорость и память стенда нет.

Поля и матрицы проверяются на небольших известных примерах. У RS проверяется
конфигурация; encode/decode явно пропускается, поскольку реализация пока отсутствует.
LDPC использует встроенную матрицу 128×64 со строками `[i, (i+1)%64, 64+i]`.
Длина сообщения — 64 бита. До измерений проверяется восстановление чистого блока.

Конфиг задаёт `seed`, `warmup`, `repetitions`, `log_level` и настройки `[ldpc]`:
`errors`, `max_iterations`, `llr_magnitude`, `llr_limit`. Значения по умолчанию
показаны в [примере](../configs/smoke.toml); неполный конфиг дополняется defaults.
`repetitions` должно быть положительным, `errors` находится в 0..=128.
Модуль LLR конечный, положительный и не превышает `llr_limit`.

Сообщения и перестановки позиций готовятся заранее независимыми генераторами
от `seed`. В каждом слове инвертируются ровно `errors` различных битов.
Прогрев не меняет измеряемые входы и исключён из результатов. Для более долгого
запуска достаточно увеличить `repetitions`; для другого уровня повреждений — `errors`.

В таблице показаны суммы внесённых, исправленных, новых и остаточных битовых
ошибок, число полностью восстановленных блоков и скорости в Mbit/s.
Новый неверный бит не считается исправлением. Совпадение с эталоном определяет
восстановление; одного допустимого синдрома недостаточно. Невосстановление
повреждённого блока — обычное наблюдение, чистого — провал проверки.
Наблюдаемые исправления не являются гарантированной корректирующей способностью.

Кодирование и декодирование измеряются отдельными пакетами из `repetitions`
вызовов. Подготовка входов и выходных слотов, проверки, логи и освобождение
результатов находятся вне таймеров. Аллокации внутри публичного API входят
в замер. Скорость — число обработанных информационных битов, делённое на
суммарное время, включая невосстановленные блоки. При нулевом времени выводится `—`.

Коды завершения: `0` — проверки прошли, `1` — провал проверки/API,
`2` — ошибка аргументов или конфигурации. CI выполняет ту же команду.

Новая smoke-проверка — обычная функция и вызов из `main`. Для нового кодека
добавляется модуль с его API и настройками; `measure::measure` и `count_errors`
переиспользуются. `measure` принимает изменяемые подготовленные входы и возвращает
нативные результаты: это подходит и для API с буферами вызывающего кода.
JSON/CSV, загрузки матриц и универсального контракта адаптеров здесь нет.

Проверки стенда:

```sh
cargo test --locked -p codelib-testkit
cargo clippy --workspace --all-targets -- -D warnings
```
