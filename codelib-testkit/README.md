# codelib-testkit

Smoke-проверки библиотеки, конфигурация, логи, скорости кодирования/декодирования
и подсчёт ошибок. Запуск из корня workspace, Rust 1.81+:

```sh
cargo run --locked --release -p codelib-testkit -- --config configs/smoke.toml
cargo run --locked --release -p codelib-testkit -- \
  --config configs/experiment.toml --csv target/experiment.csv
```

По умолчанию используется `configs/smoke.toml`; `--help` выводит справку.
Результаты идут в stdout, логи — в stderr; `RUST_LOG` переопределяет `log_level`.

CLI запускает LDPC (128 бит, сообщение 64 бита).
LDPC использует проверки `[i, (i+1)%64, 64+i]`, где `0 <= i < 64`.
Также проверяются поля, матрицы и конфигурация RS; encode/decode RS пропускается.

Общие настройки: `seed`, `warmup`, `repetitions > 0`, `log_level`.
В `[ldpc]` поле `error_counts` принимает число или непустой список
различных чисел в пределах 0..=128; точки сортируются.
У LDPC `errors` — синоним `error_counts`; одновременно задавать их нельзя.
Параметры LDPC: `max_iterations`, `llr_magnitude`, `llr_limit`. Модуль LLR
конечный, положительный и не превышает `llr_limit`. Значения по умолчанию — в
[smoke-конфиге](../configs/smoke.toml).

Сообщения и перестановки позиций готовятся независимыми генераторами от `seed`
и общие для всех точек. Большее число ошибок расширяет набор повреждений.
Прогрев каждой точки исключён из статистики и не меняет измеряемые входы.

Таймеры охватывают отдельно вызовы кодирования и декодирования, включая
аллокации API. Подготовка входов, проверки и освобождение результатов —
вне замеров. Скорость считается по информационным битам всех завершённых
испытаний: бит/с в CSV, Mbit/s в терминале.

Для N испытаний и R восстановленных блоков доля восстановления — R/N,
FER — (N−R)/N, BER (для символов — SER) — число ошибок / (N × n) по всему слову.
Исправленные, новые и остаточные ошибки считаются отдельно.
Наблюдения не гарантируют корректирующую способность; порогов скорости и FER нет.

CSV содержит строку на точку: размеры, канал, испытания, счётчики, доли,
итерации, скорости и статус. `channel` — `bit_flips` или `erasures`,
количество — `error_count` или `erasure_count`. У стираний BER/SER отсутствует.
Без полного слова хотя бы в одном испытании BER/SER после и счётчики исправлений
всей точки неизвестны. Неизвестные метрики и нулевые знаменатели дают пустые
ячейки CSV и `—` в терминале. Итерации доступны у LDPC.

`Candidate` сравнивается с оригиналом; `NeedMore` и `Stopped` — невосстановление.
Чистый невосстановленный блок или неожиданный `Err` — провал: серия прерывается,
завершённые точки сохраняются, остальные кодеки выполняются.
У сбойной точки метрики пусты, причина — в `error`. Коды завершения:
`0` — успех, включая FER > 0; `1` — провал проверки/API; `2` — ошибка аргументов,
конфигурации или записи CSV. Запись CSV поверх конфига, включая ссылки, запрещена.
CI сохраняет CSV как артефакт.

Новая smoke-проверка — функция и вызов из `main`. Пример подключения кодека —
[адаптер LDPC](src/ldpc.rs): `BlockLayout`, `CodecOps` и `BlockScenario::run`.
Длины задаются в элементах, `payload_bits` — информационные биты.
`Channel` поддерживает инверсии и стирания; `prepare` получает `None` для стираний.
`encoded` и `decoded` проверяют инварианты вне таймеров. `Trial::buffers` и
`prepare` позволяют подготовить буферы для API. LDPC использует временный
адаптер `LegacyLdpc` внутри стенда.

Проверки: `cargo test --locked -p codelib-testkit`,
`cargo clippy --workspace --all-targets -- -D warnings`.
