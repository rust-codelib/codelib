## 1. Исходное состояние и результат

В `ldpc-codes` уже реализованы:

- `Bit`, преобразования битов в `Vector<Gf2>` и обратно с сохранением длины;
- разреженная `ParityCheckMatrix`, синдром и проверка допустимости слова;
- `Encoder` и `SystematicEncoder`, информационные позиции и извлечение сообщения;
- проверяемые `DecoderConfig` и `DecodeInput`, подготовка LLR и стираний;
- `spa_step`, `SpaStepResult` и `SpaDecoder` в `src/spa.rs`; закрытый `SparseGraph` в `src/spa/graph.rs`, а `SpaState` и численное ядро — в `src/spa/state.rs`;
- независимый численный эталон в `src/spa/reference_tests.rs`.

После этапа пользователь сможет создать согласованные кодер и декодер одной проверочной матрицы `H`, закодировать один блок, декодировать LLR до нулевого синдрома или лимита итераций, получить диагностику и подключить журнал событий. При известном переданном слове можно отдельно посчитать реальные битовые ошибки.

Уточнение относительно старых описаний: вводный статус `PLAN-1.md` устарел, его будущие контракты реализованы частично. При разработке сверяться с кодом, а сигнатуры декодера и конфигуратора сохранить согласно этому плану.

### Границы

Работа относится к одному блоку из `k` информационных битов и `n` битов кодового слова. Не добавляются упаковка байтов, разбиение целого сообщения на блоки, модель канала, Min-sum, измерение производительности или общая тестирующая система.

Общий тип полинома и адаптер `Vector<F> ↔ полином` остаются этапом 6. Этот этап выполняет требования ТЗ о декодере, конфигураторе, диагностике и логировании в битовом API, но не завершает всё ТЗ. Полный перебор кода, property-тесты и итоговое обновление корневого README остаются этапом 5.

Не менять арифметику `gf2m`, `gfpm`, API `gf-linalg` или контракты `rs-codes`. Новые сторонние зависимости, `unsafe`, заглушки и подавления предупреждений не нужны.

## 2. Публичный API

Все элементы ниже реализованы и экспортированы из корня `ldpc_codes`.

### 2.1. Декодер

```rust
pub trait Decoder {
    fn codeword_len(&self) -> usize;
    fn decode(
        &mut self,
        input: DecodeInput<'_>,
        observer: Option<&mut dyn DecodeObserver>,
    ) -> Result<DecodeResult, LdpcError>;
}

pub struct SpaDecoder { /* закрытые поля */ }

impl SpaDecoder {
    pub fn try_new(
        checks: ParityCheckMatrix,
        config: DecoderConfig,
    ) -> Result<Self, LdpcError>;
}

impl Decoder for SpaDecoder { /* рабочая реализация */ }
```

`trait` задаёт общий контракт поведения. `&mut self` — временная изменяемая ссылка: декодер обновляет и повторно использует собственные рабочие буферы. `DecodeInput` заимствует входные массивы только на время вызова. Декодер и результат не сохраняют ссылки на них.

`try_new` принимает исходную `H` во владение, строит граф один раз и выделяет состояние через существующий `SpaState::try_new`. Любая уже допустимая `ParityCheckMatrix` подходит декодеру, включая нулевой и полный ранг. Условие `0 < rank(H) < n` относится к кодеру и общему конфигуратору. Для самостоятельного декодера вычисление RREF не требуется.

Параметры остаются неизменными: по умолчанию 50 итераций, предел LLR 20; допустим конечный предел из `(0, 20]` и любой бюджет `usize`, включая 0. Численная политика полностью наследуется из `PLAN-3.md`.

### 2.2. Результат

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum DecodeStatus {
    ParitySatisfied,
    IterationLimit,
}

#[derive(Debug, Clone, PartialEq)]
pub struct DecodeResult { /* закрытые поля */ }

impl DecodeResult {
    pub fn try_new(
        checks: &ParityCheckMatrix,
        initial_word: &[Bit],
        posterior_llrs: Vec<f64>,
        status: DecodeStatus,
        iterations: usize,
        iteration_limit: usize,
    ) -> Result<Self, LdpcError>;
    pub fn word(&self) -> &[Bit];
    pub fn posterior_llrs(&self) -> &[f64];
    pub fn syndrome(&self) -> &[Bit];
    pub fn status(&self) -> DecodeStatus;
    pub fn iterations(&self) -> usize;
    pub fn changed_bits(&self) -> usize;
    pub fn initial_unsatisfied_checks(&self) -> usize;
    pub fn final_unsatisfied_checks(&self) -> usize;
}
```

Результат владеет отдельными массивами: слово и posterior имеют длину `n`, синдром — `m`. Он остаётся доступным и неизменным после следующего вызова декодера. Поля закрыты; внешний декодер может создать результат через проверяемый `DecodeResult::try_new`. `Eq` не реализуется из-за `f64`.

Инварианты результата:

- `word[i]` — жёсткое решение по `posterior_llrs[i]`, в исходном порядке столбцов `H`;
- все posterior конечны; SPA дополнительно ограничивает их диапазоном конфигурации;
- `syndrome` вычислен по исходной `H` для итогового слова;
- `final_unsatisfied_checks` равен числу единиц итогового синдрома;
- `ParitySatisfied` эквивалентен нулевому итоговому синдрому;
- при `IterationLimit` синдром ненулевой и число итераций равно бюджету;
- `changed_bits` — расстояние между начальным и итоговым жёсткими решениями, а не сумма изменений за итерации.

`try_new` строит слово по знакам `posterior_llrs`, а синдром и счётчики — по `H` и переданному `initial_word`. Он проверяет длины, конечность posterior, число итераций относительно бюджета и согласованность статуса. При `iterations == 0` итоговое слово должно совпадать с начальным. Для SPA начальное решение определяется после насыщения LLR и применения стираний. Внешний алгоритм сам отвечает за соответствие `initial_word` своему исходному каналу и за фактическое выполнение объявленных итераций: конструктор не хранит историю алгоритма и не может её проверить. При остановке SPA до первого шага posterior равен подготовленному канальному массиву, `iterations = 0`, `changed_bits = 0`, начальный и итоговый счётчики совпадают.

### 2.3. Получатель событий

```rust
pub trait DecodeObserver {
    fn on_event(&mut self, event: &DecodeEvent);
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum DecodeEvent {
    Started {
        unsatisfied_checks: usize,
    },
    IterationFinished {
        iteration: usize,
        unsatisfied_checks: usize,
        changed_bits: usize,
    },
    Finished {
        iterations: usize,
        status: DecodeStatus,
        unsatisfied_checks: usize,
        changed_bits: usize,
    },
}
```

`Option` обозначает наличие или отсутствие получателя: `None` выключает события. `dyn DecodeObserver` позволяет передать любой тип, реализующий этот контракт, без привязки декодера к конкретному журналу. Callback вызывается синхронно; ссылка на событие действует только внутри вызова. Для хранения получатель копирует событие.

`Started` описывает начальное решение, то есть итерацию 0 с нулём изменённых битов. `IterationFinished` использует номера от 1 и показывает расстояние от текущего слова до начального. `Finished` совпадает с итоговыми полями результата. Массивы сообщений и слов в события не входят.

Для корректного входа порядок строго такой: один `Started`, по одному `IterationFinished` на полностью выполненную итерацию, один `Finished`. При нуле итераций событий ровно два. Неверный ввод возвращает ошибку до любого события.

Получатель передаётся для конкретного вызова и не хранится декодером. Без него журнал и история итераций не выделяются. Логирование не влияет на вычисления и результат. Ошибка записи файла принадлежит приложению: получатель может сохранить её у себя, но она не превращается в `LdpcError` и не меняет статус декодирования.

### 2.4. Конфигуратор

```rust
pub struct LdpcConfigurator;
pub struct ConfiguredLdpc { /* закрытые поля */ }

impl LdpcConfigurator {
    pub fn build(
        checks: ParityCheckMatrix,
        config: DecoderConfig,
    ) -> Result<ConfiguredLdpc, LdpcError>;
}

impl ConfiguredLdpc {
    pub fn encoder(&self) -> &SystematicEncoder;
    pub fn decode(
        &mut self,
        input: DecodeInput<'_>,
        observer: Option<&mut dyn DecodeObserver>,
    ) -> Result<DecodeResult, LdpcError>;
}
```

Согласованная пара создаётся только через `build`; пользователь не задаёт отдельно `m`, `n`, ранг или `k`. `SystematicEncoder` получает ранг единственным RREF и определяет `k = n - rank(H)`. Граф декодера строится по исходным строкам `H`, включая зависимые и пустые строки, без перестановок кодера. `ConfiguredLdpc::decode` делегирует внутреннему SPA-декодеру, не раскрывая изменяемую ссылку, через которую можно было бы заменить его и нарушить согласованность пары.

Конфигуратор передаёт матрицу кодеру по значению: кодер хранит исходную `H`. После успешной подготовки кодера внутренний конструктор SPA-декодера получает ссылку на эту матрицу и строит граф и рабочие буферы, не сохраняя ссылку. Публичный `SpaDecoder::try_new` по-прежнему принимает матрицу по значению и использует тот же внутренний borrowed-конструктор. При сборке пары глубокая копия `H` не нужна; временная ссылка не требует `Arc` или совместного владения.

Сначала подготовить кодер. Если его ранг недопустим, вернуть существующую `InvalidEncoderRank`, не строя декодер. Затем подготовить декодер и вернуть пару только после полного успеха. Если второй шаг завершается ошибкой, локально созданный кодер освобождается; частичная пара наружу не выходит.

### 2.5. Сравнение с эталоном

```rust
pub fn count_bit_errors(
    word: &[Bit],
    reference: &[Bit],
) -> Result<usize, LdpcError>;
```

Функция считает позиции несовпадения двух массивов равной длины. Она не зависит от `H` и подходит как для кодовых слов, так и для информационных сообщений. Пустые массивы дают 0; данные не меняются. Разная длина возвращает новый вариант `LdpcError::ReferenceLengthMismatch { expected: usize, actual: usize }`, где `expected = word.len()`, `actual = reference.len()`. Добавить документацию, `Display` и проверки этого варианта, сохранив `Eq` и существующую цепочку `source`.

Число ошибок до и после декодирования получается двумя вызовами с одним эталоном: для начального решения и итогового слова. Их разность — чистое уменьшение числа ошибок, а не число всех правильно изменённых позиций. Не смешивать сравнение кодового слова длины `n` со сравнением сообщения длины `k`.

Эталон не входит в `decode`: обычный приёмник его не знает. `changed_bits`, число невыполненных проверок и статус не заменяют сравнение с эталоном. Например, для повторного кода допустимы и `000`, и `111`; положительные LLR при переданном `111` могут дать `ParitySatisfied`, `changed_bits = 0`, но три ошибки относительно эталона.

## 3. Цикл декодирования и состояние

`SpaDecoder` разместить в `src/spa.rs`, а закрытое состояние и численное ядро — в `src/spa/state.rs`. Узкие внутренние модули позволяют повторно использовать ядро без раскрытия его полей или дублирования арифметики. Контракт, результат и события разместить в `src/decoder.rs`.

Один вызов `decode` выполняется так:

1. Подготовить блок через существующий `SpaState::prepare_block`. Порядок ошибок сохраняется: длина LLR → конечность всех значений → границы всех стираний → повторы. Проверяется даже NaN на стираемой позиции. Для поиска повторов повторно используется маска: при ошибке повторов она может остаться очищенной или частично заполненной, но `channel`, `q`, `r`, `posterior` и `word` не меняются. После успешной проверки новые LLR записываются в уже выделенный канал.
2. После успешной подготовки сбросить счётчики, сохранить начальное жёсткое слово и вычислить его синдром. Отправить `Started`.
3. При нулевом синдроме сразу вернуть `ParitySatisfied` с нулём итераций. Это правило имеет приоритет даже при бюджете 0.
4. Если начальный синдром ненулевой и бюджет равен 0, вернуть `IterationLimit` без шага SPA.
5. Пока число выполненных итераций меньше бюджета, выполнить `SpaState::step`, увеличить счётчик и вычислить синдром. Только при наличии наблюдателя вычислить `changed_bits` этой итерации и отправить `IterationFinished`.
6. После каждого шага сначала проверить нулевой синдром. Остановиться на первой успешной итерации, в том числе на последней разрешённой. Если успеха нет и бюджет исчерпан, выбрать `IterationLimit`.
7. Сформировать результат с копиями итоговых массивов и отправить один `Finished` с теми же показателями.

Не вызывать публичный `spa_step` внутри цикла: он каждый раз создаёт новое состояние и теряет сообщения предыдущей итерации. Не подавать posterior как новый канальный вход: `channel` фиксирован на весь блок, а между шагами сохраняются `q` и `r`.

Перед следующим корректным блоком `prepare_block` перезаписывает канал, очищает маску стираний, сбрасывает `r` и временные массивы, восстанавливает `posterior`, `q` и начальное `word`. Ошибка входа не меняет предыдущее содержательное состояние, не порождает события и не влияет на последующий корректный вызов; служебная маска может измениться при проверке повторов. Проверить это на уровне декодера, даже несмотря на готовые тесты ядра.

Граф и основные буферы, включая канал и маску стираний, переиспользуются. Дополнительное хранение начального слова, синдрома и результата занимает `O(m + n)`; итоговая память декодера остаётся `O(m + n + E)`. Подготовка и каждый шаг требуют `O(m + n + E)`; `O(n)` расстояние для события итерации считается только с наблюдателем, а итоговое расстояние всегда нужно результату. История не хранится внутри декодера и память под бюджет не выделяется.

Новые размеры буферов проверять на переполнение теми же средствами, что в ядре. Нехватка памяти отдельно не преобразуется в `LdpcError`, как и в существующем коде с обычным `Vec`.

## 4. Контрольные случаи

### 4.1. Два шага с независимым ручным расчётом

```text
H = [[1, 1, 0],
     [0, 1, 1]]
channel = [2, -3, 4], llr_limit = 20

начало: posterior = [2, -3, 4], word = [0, 1, 0], syndrome = [1, 1]
шаг 1: posterior = [-1, 3, 1], word = [1, 0, 0], syndrome = [1, 0]
шаг 2: posterior = [3, 3, 3], word = [0, 0, 0], syndrome = [0, 0]
```

Для бюджета 0 ожидаются начальные массивы, `IterationLimit`, `changed_bits = 0`. Для бюджета 1 — результат первого шага, `IterationLimit`, `changed_bits = 2`. Для бюджета 2 и выше — остановка на втором шаге, `ParitySatisfied`, `changed_bits = 1`. Начальный счётчик проверок во всех случаях равен 2; итоговые — 2, 1 и 0 соответственно.

Этот пример обнаруживает потерю состояния, неправильный учёт бюджета и накопление изменений вместо сравнения с начальным решением. Все его численные значения сравниваются точно: проверки степени 2 используют готовое точное правило.

### 4.2. Обязательные проверки поведения

| Случай | Ожидаемое поведение |
| --- | --- |
| Безошибочное допустимое слово | `ParitySatisfied`, 0 итераций, posterior равен подготовленному channel |
| Нулевой бюджет | Сначала проверить синдром; корректный результат при обоих статусах |
| Успех на границе бюджета | `ParitySatisfied`, без лишнего шага или ложного `IterationLimit` |
| Ошибки LLR и стираний | Существующие конкретные ошибки, заданный порядок, отсутствие событий |
| Стирания | Начальное решение и `changed_bits` считаются после зануления LLR; вход не меняется |
| Все LLR нулевые или все биты стёрты | Начальное слово нулевое, остановка на итерации 0; это не гарантия восстановления эталона |
| Нулевая H, изолированные биты | Самостоятельный декодер работает; изолированные биты сохраняют подготовленное канальное решение |
| Полноранговая H | Самостоятельный декодер создаётся; конфигуратор отклоняет ранг через кодер |
| Повторяющиеся и пустые строки | Синдром длины `m` в исходном порядке; повторные проверки учитываются отдельно |
| Повторные вызовы | Результат как у нового декодера; предыдущий результат не меняется |
| Корректный → ошибочный → корректный вход | Нет частичного сброса и событий ошибочного вызова; последний блок независим |
| Получатель подключён или отсутствует | Одинаковы слово, LLR, синдром, статус и все счётчики |
| События | Порядок, номера и показатели совпадают с состоянием и итоговым результатом |
| Другое допустимое слово | Нулевой синдром совместим с ненулевыми ошибками относительно эталона |
| Сравнение с эталоном | Совпадение, несколько различий, пустые массивы и ошибка длины |

Для двух наборов LLR из раздела 5 `GENERAL-PLAN.md` проверить восстановление `[0, 0, 1, 0, 1, 1]` и нулевой синдром. Первый должен остановиться за одну итерацию. Для второго установить ожидаемое число итераций независимым эталонным циклом с принятой численной политикой, затем записать его в тест; не брать ожидание из вывода самого `SpaDecoder`.

Для нелинейных LLR использовать допуск по образцу этапа 3 и отдельно проверять конечность. Синдром контрольных примеров сверять с независимым плотным XOR-расчётом. Полный перебор сообщений и property-тесты всего кодека здесь не требуются.

## 7. Риски и ограничения

| Риск | Решение |
| --- | --- |
| Повторный запуск одного шага вместо продолжения SPA | Использовать одно `SpaState` внутри цикла; проверить ручной пример из двух шагов |
| Принять нулевой синдром за доказательство восстановления | Документировать смысл статуса и тестировать другое допустимое слово с эталоном |
| Спутать изменённые биты с исправленными ошибками | Хранить начальное решение после стираний; точные ошибки считать отдельным сравнением |
| Перенести перестановки или удалить зависимые строки в декодере | Строить граф и синдром по исходной `H`; перестановки использовать только в кодере |
| Утечка состояния между блоками | Сбрасывать через `prepare_block`; проверить последовательность с ошибочным входом |
| Различия численных функций на платформах | Проверять конечность и применять допуск к нелинейным LLR; использовать независимый эталон |

SPA не гарантирует сходимость или исправление любого количества ошибок. Подсказка позиции означает стирание LLR, а не обязательную инверсию. Предел каждой оси `H` остаётся 4096; предел сообщения 4096 байт относится к будущему байтовому слою. Общий полином, BER/FER по модели канала, другие алгоритмы и оптимизации требуют отдельных этапов или запросов.

Описанный битовый API реализован и проверен. Этапы 5–6 не начаты; для продолжения требуется отдельный запрос пользователя.
