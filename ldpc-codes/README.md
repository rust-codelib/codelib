# ldpc-codes

Библиотечный crate для двоичных LDPC-кодов. Он предоставляет бит `Bit`, преобразование битов и векторов над GF(2), разреженную проверочную матрицу `H`, вычисление синдрома, систематический кодер и публичный `spa_step` для одного flooding-шага SPA.

## Систематический кодер

`SystematicEncoder::try_new(checks)` создаёт кодер по проверочной матрице. Метод получает `checks` по значению: владение матрицей переходит кодеру, который хранит её для последующей проверки синдрома. Дополнительных настраиваемых параметров у кодера нет. Методы кодирования и извлечения читают состояние и не меняют его.

Пусть `m` — число строк `H`, `n` — число столбцов, `r = rank(H)`, а `k = n - r`. Кодер строится, только если `0 < r < n`. Зависимые строки допустимы: длина сообщения определяется рангом, а не числом строк. Непивотные столбцы RREF, перечисленные по возрастанию, становятся информационными; опорные — проверочными.

Все позиции слова относятся к столбцам исходной `H`. Поэтому `message[j]` попадает в `word[information_positions()[j]]`; первые `k` битов слова могут не быть сообщением. `encode` принимает ровно `k` битов и возвращает слово из `n` битов. Читающие методы кодера — `rank`, `message_len`, `codeword_len`, `information_positions` и `parity_positions`. Для вызова `encode`, `extract_message`, `message_len` и `codeword_len` нужно импортировать trait `Encoder` — в Rust методы, объявленные в trait, становятся доступны в области видимости через импорт этого trait.

`extract_message` сначала проверяет длину слова, затем его синдром по исходной `H`. Неверная длина даёт `WordLengthMismatch`, слово с ненулевым синдромом — `InvalidCodeword`. Любое слово правильной длины с нулевым синдромом считается допустимым и проходит извлечение. Без известного исходного слова или сообщения кодер не может определить, было ли это слово передано на самом деле: нулевой синдром подтверждает только выполнение проверок `H`.

Запускаемый пример ниже использует `H` с зависимой строкой. Он показывает точные позиции, слово и обратное извлечение:

```sh
cargo run -p ldpc-codes --example systematic_encode
```

В исходнике примера метод `encode` вызывается через импортированный `Encoder`:

```rust
use ldpc_codes::{Bit, Encoder, LdpcError, ParityCheckMatrix, SystematicEncoder};

fn main() -> Result<(), LdpcError> {
    let checks = ParityCheckMatrix::try_from_rows(
        6,
        vec![vec![0, 1, 3], vec![1, 2, 4], vec![0, 4, 5], vec![2, 3, 5]],
    )?;
    let encoder = SystematicEncoder::try_new(checks)?;
    let message = [Bit::Zero, Bit::One, Bit::One];
    let word = encoder.encode(&message)?;

    assert_eq!(encoder.information_positions(), &[3, 4, 5]);
    assert_eq!(word, [Bit::Zero, Bit::Zero, Bit::One, Bit::Zero, Bit::One, Bit::One]);
    assert_eq!(encoder.extract_message(&word)?, message);
    Ok(())
}
```

Полный пример с проверками ранга и проверочных позиций находится в [`examples/systematic_encode.rs`](examples/systematic_encode.rs). Пример преобразования битов и проверки синдрома находится в [`examples/syndrome.rs`](examples/syndrome.rs) и запускается командой `cargo run -p ldpc-codes --example syndrome`.

## Один шаг SPA

`spa_step(&checks, config, input)` выполняет ровно один flooding-шаг алгоритма Sum-Product по разреженным рёбрам `H`: сначала обновляет сообщения проверок, затем posterior LLR и сообщения битов для следующего шага. Соглашение о знаке: `L = ln(P(0) / P(1))`; при `L >= 0` жёсткое решение — `Bit::Zero`, иначе — `Bit::One`. Оба значения `+0.0` и `-0.0` дают `Zero`.

`DecoderConfig::default()` задаёт бюджет 50 и предел LLR 20.0. `DecoderConfig::try_new(max_iterations, llr_limit)` принимает любой бюджет, включая 0, и только конечный предел из диапазона `0 < llr_limit <= 20`. Входные конечные LLR ограничиваются этим пределом; q, r и итоговые posterior LLR также насыщаются до `±llr_limit`. NaN и бесконечность возвращают ошибку, даже если такой бит указан как стёртый. Стирание означает неизвестный бит: после проверок входа его канальный LLR устанавливается в `0.0`, значение не инвертируется. Проверки идут в порядке: длина LLR, первое не конечное LLR, первый индекс стирания вне границ, первый повтор индекса.

Шаг работает с любой допустимой разреженной `H`, независимо от её ранга: разрешены изолированные биты и проверки степеней 0, 1 и 2, пустые и повторяющиеся строки.

Бюджет итераций `spa_step` не применяет: даже при бюджете 0 функция выполняет один шаг. Каждый вызов создаёт новое рабочее состояние, а результат владеет новыми массивами слова и posterior LLR длины `n` в порядке столбцов исходной `H`. Начальный нулевой синдром не пропускает шаг. Нулевой синдром полученного слова говорит только, что оно удовлетворяет проверкам `H`.

`DecodeInput` содержит заимствованные ссылки на массивы канальных LLR и стираний. Ссылка позволяет передать существующий массив без передачи владения: вызывающая сторона продолжает владеть `channel`, а функция не меняет и не сохраняет его. `spa_step` возвращает `Result<SpaStepResult, LdpcError>`: это либо успешный результат, либо ошибка; оператор `?` в `main() -> Result<(), LdpcError>` возвращает ошибку вызывающему коду.

```rust
use ldpc_codes::{spa_step, Bit, DecodeInput, DecoderConfig, LdpcError, ParityCheckMatrix};

fn main() -> Result<(), LdpcError> {
    let checks = ParityCheckMatrix::try_from_rows(3, vec![vec![0, 1], vec![1, 2]])?;
    let channel = [2.0, -1.0, 3.0];
    let result = spa_step(
        &checks,
        DecoderConfig::try_new(0, 20.0)?,
        DecodeInput { llrs: &channel, erasures: &[] },
    )?;

    assert_eq!(result.posterior_llrs(), &[1.0, 4.0, 2.0]);
    assert_eq!(result.word(), &[Bit::Zero, Bit::Zero, Bit::Zero]);
    assert_eq!(checks.syndrome(result.word())?, vec![Bit::Zero, Bit::Zero]);
    Ok(())
}
```

Запустить этот пример можно командой `cargo run -p ldpc-codes --example spa_step`; полный файл находится в [`examples/spa_step.rs`](examples/spa_step.rs). Для `m` проверок, `n` битов и `E` единиц матрицы шаг занимает `O(m + n + E)` времени и временной памяти.

`spa_step` всегда выполняет один шаг. Для полного цикла итераций используйте `SpaDecoder`; следующий пример показывает, как получать его события.

## Журнал событий

`DecodeObserver` получает события синхронно: начальное решение, каждую завершённую итерацию и итог остановки. Передайте наблюдателя как `Some(&mut observer)` в `decode`; `None` выключает события. При ошибке входных данных событий нет. Наблюдатель может печатать их, как в примере ниже, или копировать `DecodeEvent` в `Vec` для последующей обработки.

Запустить stdout-пример можно командой:

```sh
cargo run -p ldpc-codes --example decode_with_log
```

`changed_bits` показывает число позиций, отличающихся от начального жёсткого решения. Это диагностическая величина, а не число исправленных ошибок: без переданного эталонного слова декодер не знает, какие изменения совпали с исходным словом. Статус и число нарушенных проверок описывают остановку и синдром результата.

## Остальной API

- `Bit` — `Zero` или `One`. `Bit::try_from(u8)` принимает только 0 и 1; `u8::from(bit)` выполняет обратное преобразование.
- `Gf2` — псевдоним `gfpm::Gf<2, 1, 1>`, элемент поля GF(2).
- `bits_to_vector(&[Bit])` создаёт новый `gf_linalg::Vector<Gf2>`, сохраняя порядок, длину, пустой ввод и хвостовые нули. Входной срез не меняется. `vector_to_bits(&Vector<Gf2>)` также создаёт отдельный результат и проверяет каждый элемент. Для значения вне нуля и единицы поля возвращается `InvalidFieldElement { index, value }`; проверка обнаруживает и неканонические элементы, созданные через `Gf::from_coeffs` в release-сборке.
- `ParityCheckMatrix::try_from_rows(bits, rows)` строит матрицу по спискам индексов единиц. `rows()`, `cols()` и `edge_count()` возвращают число проверок `m`, битов `n` и единиц `E`. `check_bits(check)` возвращает отсортированные индексы битов проверки, а `bit_checks(bit)` — проверки для бита. Для существующей пустой смежности оба метода возвращают `Some(&[])`; для индекса за границей — `None`.
- `syndrome(word)` возвращает по одному XOR-результату на строку `H`; `is_codeword(word)` возвращает `true`, если синдром нулевой. Обе операции принимают только слово длины ровно `n`, иначе возвращается `WordLengthMismatch`.

Каждая ось `ParityCheckMatrix` должна иметь размер от 1 до `MAX_MATRIX_DIM` включительно; сейчас максимум равен 4096. Пустые и повторяющиеся строки допустимы, но повтор одного индекса внутри строки запрещён. Матрица хранит смежности разреженно, с расходом памяти `O(m + n + E)`.

## Ошибки

Операции возвращают `Result<_, LdpcError>`. Ошибки входных данных сообщают о недопустимом бите или элементе поля, размерах матрицы, индексе, повторном бите, неверной длине слова или сообщения, недопустимом ранге кодера, ненулевом синдроме и переполнении размера. В `InvalidCodeword { unsatisfied_checks }` число нарушенных проверок считает все строки исходной `H`, включая повторяющиеся. Если операция `gf-linalg` завершилась ошибкой, `LdpcError::LinearAlgebra` сохраняет исходную `LinalgError` в поле `source`; цепочку причины можно получить через стандартный `std::error::Error::source`.

При `extract_message` неверная длина обнаруживается до вычисления синдрома. Это позволяет отличить ошибку формы входа (`WordLengthMismatch`) от слова нужной длины, которое нарушает проверки (`InvalidCodeword`).

## Зависимости, стоимость и пределы

Крейт использует стандартную библиотеку Rust и `Vec`, поэтому не поддерживает `no_std`. Он зависит от уже имеющихся в workspace `gfpm` и `gf-linalg`; новых сторонних зависимостей нет.

Подготовка кодера один раз преобразует разреженную `H` в плотную матрицу и вычисляет её RREF. Для ранга `r`, размера `m × n` и `k = n - r` это требует порядка `O(mnr)` операций поля и `O(mn)` временной плотной памяти. Кодер хранит разреженную исходную матрицу, обе перестановки столбцов и плотные коэффициенты проверочных битов `B` размера `r × k`, то есть `O(m + n + E + rk)` памяти. Кодирование умножает `B` на вектор сообщения за `O(rk)` операций поля; заполнение и перестановка слова требуют `O(n)`.

Проверки переполнения размеров возвращают `SizeOverflow`, но нехватка памяти отдельно не преобразуется в `LdpcError`: для выделения буферов используется обычный `Vec`. Предел каждой оси матрицы — 4096, поэтому `n` не больше 4096, а `k` измеряется в битах одного блока. Этот API не принимает байтовое сообщение и не выполняет его упаковку или разбиение на блоки. Указанный в требованиях предел исходного сообщения в 4096 байт относится к будущему байтовому слою. Предел 128 КиБ относится к отдельным преобразованиям `gf-linalg` в массивы коэффициентов полиномов и к этому битовому кодеру не применяется; общий тип полинома ещё не реализован.

Полный SPA-декодер реализован: он возвращает слово, статус остановки и диагностику по итоговому синдрому. Подробный пример пути от сообщения до восстановления и описание API будут добавлены в следующей задаче этапа 4. Интеграция с общим типом полинома отложена до этапа 6.
