# gf-poly

`Polynomial<F>` над статическими конечными полями: создание, равенство,
текстовый ввод/вывод и преобразование байтовых сообщений.
Rust 1.81+ · `std` · `unsafe` запрещён.

## Использование

```rust
use gf2m::Gf256;
use gf_poly::{Polynomial, PolynomialError};

let polynomial = Polynomial::try_new(vec![Gf256::one(), Gf256::zero()])?;
assert_eq!(polynomial.degree(), Some(0));
assert_eq!(polynomial.to_string(), "polynomial 2 0x01 0x00");
let restored: Polynomial = polynomial.to_string().parse()?;
assert_eq!(restored.coefficients(), polynomial.coefficients());

let message = [0x83, 0x00];
let bits = Polynomial::<Gf256>::try_from_message(&message)?;
assert_eq!(bits.try_to_message()?, message);
# Ok::<(), PolynomialError>(())
```

## Хранение и равенство

Коэффициент `i` относится к `x^i`; хранение — `Box<[F]>`. `try_new(Vec<F>)`
и `TryFrom<Box<[F]>>` принимают данные во владение, `try_from_slice` копирует
срез. `coefficients()` возвращает срез, `into_coefficients()` — сам массив.
Длина и хвостовые нули сохраняются.

`PartialEq`/`Eq` игнорируют старшие нули: `[a] == [a, 0, 0]`. Пустой массив
и массив из одних нулей задают нулевой многочлен; его `degree()` равна `None`.
Сравниваются формальные многочлены, а не их значения в точках поля.

Поддерживаются статические `gf2m::Gf` и `gfpm::Gf`, по умолчанию — `Gf256`.
Разные поля, включая разные модули одного порядка, дают разные типы.
Пользовательскому полю нужен [`FieldElement`], а для текста — [`FieldText`].

## Текстовый формат

`polynomial N c0 c1 ...`, где `N` — число сохранённых коэффициентов.
Поле выбирается типом при чтении. Разделители — ASCII-пробельные символы,
длина — десятичные ASCII-цифры без знака; ведущие нули допустимы.

Токены задаёт `FieldText`: для `gf2m` это `0x` и фиксированное число hex-цифр,
для `gfpm` — десятичный упакованный код элемента. Допустим один знак вплотную
к токену. Минус отрицает элемент поля: например, в GF(9) `-3` означает `-x`
и выводится кодом `6`, а в характеристике 2 `-a = a`.
Собственный разбор пользовательского `FieldText` имеет приоритет перед знаком.
Ошибки ввода возвращаются как [`PolynomialError`].

## Сообщения и ограничения

[`MAX_POLYNOMIAL_BYTES`] — 128 КиБ по `len * size_of::<F>()`, включая хвостовые
нули, без метаданных `Box` и расходов аллокатора. Все конструкторы проверяют
предел до копирования данных, в том числе в release.

`try_from_message` представляет байт восемью коэффициентами `0`/`1` поля,
младший бит первым. `try_to_message` восстанавливает байты, требуя кратную
восьми длину массива и только нули и единицы. Порядок, длина и нулевые байты
сохраняются. Это битовое представление для любого GF, а не один символ GF(256)
на байт. Равенство полиномов не означает равенство длин исходных сообщений.

Оба метода проверяют [`MAX_MESSAGE_BYTES`] — 4096 байт. Предел памяти
коэффициентов действует отдельно и для крупных `F` может быть строже.
Длина текстовой записи многочлена не ограничивается 4096 байтами.

## Интеграция и проверки

`gf-linalg` реэкспортирует общие трейты и предел коэффициентов. Его массивы
коэффициентов совместимы с `TryFrom<Box<[F]>>` и `into_coefficients()`;
преобразования векторов и строк матриц сохраняют их длину.

```sh
cargo test -p gf-poly
cargo test -p gf-poly --release
cargo clippy -p gf-poly --all-targets -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc -p gf-poly --no-deps
```
