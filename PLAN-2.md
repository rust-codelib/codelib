# Этап 2: систематическое кодирование в `ldpc-codes`

**Статус:** этап 2 выполнен (задачи 2.1–2.5). `SystematicEncoder` и `Encoder` реализованы и экспортируются из корня `ldpc_codes`.

Основание — «Этап 2 — систематическое кодирование» из [GENERAL-PLAN.md](GENERAL-PLAN.md), контракты раздела 4.1 [PLAN-1.md](PLAN-1.md) и требования [Codelib.md](Codelib.md). Спецификация, решения и список задач собраны здесь по принятой в проекте схеме `PLAN-N.md`; отдельные `SPEC.md` и `tasks/todo.md` не нужны.

## 1. Исходное состояние и результат

В коде уже есть:

- `Bit`, `Gf2`, `bits_to_vector` и `vector_to_bits`;
- проверяемая разреженная `ParityCheckMatrix`, обе смежности, синдром и `is_codeword`;
- `Matrix<F>::rref()`, `RrefResult::matrix()`, `pivot_columns()` и `rank()`;
- умножение `Matrix<F>` на `Vector<F>` через `try_mul_vector`.

Вводные статусы `GENERAL-PLAN.md` и `PLAN-1.md` устарели: основа LDPC уже реализована. Для этого этапа ориентируемся на код и README, а не повторяем этапы 0 и 1. RREF сохраняет исходный порядок столбцов: отображение систематических позиций строится отдельно.

После реализации пользователь сможет:

1. Создать кодер из проверочной матрицы `H`.
2. Узнать длины сообщения и кодового слова, ранг и информационные позиции.
3. Закодировать ровно `k` битов в допустимое слово длины `n`.
4. Извлечь сообщение из слова, удовлетворяющего исходной `H`.

Здесь `m` — число строк `H`, `n` — число столбцов, `r = rank(H)`, `k = n - r`. Систематическое кодирование означает, что исходные информационные биты присутствуют в кодовом слове без изменения, на заранее определённых позициях.

### Границы этапа

Вход и выход — один блок битов. Внутри кодирования используется `Vector<Gf2>`, как требует контракт первого этапа. Зависимые и нулевые строки поддерживаются; кодер разрешён только при `0 < r < n`.

SPA, `Decoder`, `DecoderConfig`, конфигуратор, события декодирования, упаковка байтов, разбиение сообщения на блоки и настоящий тип полинома относятся к следующим этапам. Их заглушки здесь не добавляются. Общая порождающая матрица нужна только в тестах: публичный метод её построения в этот этап не входит.

Арифметика `gf2m`, `gfpm`, реализации `gf-linalg`, контракты `rs-codes`, зависимости и CI не требуют изменений.

## 2. Публичный API

### 2.1. Контракт кодера

Сохранить сигнатуры из `PLAN-1.md`:

```rust
pub trait Encoder {
    fn message_len(&self) -> usize;
    fn codeword_len(&self) -> usize;
    fn encode(&self, message: &[Bit]) -> Result<Vec<Bit>, LdpcError>;
    fn extract_message(&self, word: &[Bit]) -> Result<Vec<Bit>, LdpcError>;
}
```

`trait` — общий контракт поведения: другой алгоритм кодирования позже сможет реализовать те же методы. `&self` и `&[Bit]` — ссылки: вызов читает кодер и входные биты без передачи владения. `Result` содержит либо `Ok(результат)`, либо `Err(причина отказа)`.

### 2.2. Конкретный систематический кодер

```rust
pub struct SystematicEncoder {
    // Закрытые поля; создаётся только проверяемым конструктором.
}

impl SystematicEncoder {
    pub fn try_new(checks: ParityCheckMatrix) -> Result<Self, LdpcError>;
    pub fn rank(&self) -> usize;
    pub fn information_positions(&self) -> &[usize];
    pub fn parity_positions(&self) -> &[usize];
}

impl Encoder for SystematicEncoder {
    // Рабочие реализации всех четырёх методов контракта.
}
```

`try_new` принимает `H` во владение: после вызова исходная переменная матрицы больше не используется. Кодер хранит исходные разреженные проверки для `extract_message`. Ссылку на изменяемую `H` наружу не выдавать.

`information_positions()` — возрастающие номера свободных столбцов RREF в исходной `H`. Бит `message[j]` находится в `word[information_positions()[j]]`.

`parity_positions()` — возрастающие номера опорных столбцов, по одному для каждой ненулевой строки RREF. Их длина равна `r`, длина информационных позиций — `k`.

Размеры сообщения и слова выводятся из матрицы; пользователь не передаёт отдельный `k`. Поля закрыты, публичного конструктора из готовых перестановок или коэффициентов нет. Методы контракта реализовать в `impl Encoder`, без дублирующих одноимённых inherent-методов. Для вызова `encode` пользователь импортирует `Encoder`.

Отображение систематических позиций остаётся внутренним. На этом этапе не вводить публичный `CodeLayout`, публичный номер ребра или общий тип перестановки. Совместное владение графом будущего кодера и декодера решается внутри конфигуратора на этапе 4; текущий публичный конструктор не требует заранее вводить `Arc` или времена жизни.

### 2.3. Пример использования

Фрагмент показывает публичный API; запускаемый пример с зависимой строкой находится в [`ldpc-codes/examples/systematic_encode.rs`](ldpc-codes/examples/systematic_encode.rs).

```rust
use ldpc_codes::{Bit, Encoder, LdpcError, ParityCheckMatrix, SystematicEncoder};

fn main() -> Result<(), LdpcError> {
    let checks = ParityCheckMatrix::try_from_rows(
        3,
        vec![vec![0, 2], vec![1, 2]],
    )?;
    let encoder = SystematicEncoder::try_new(checks)?;

    assert_eq!(encoder.rank(), 2);
    assert_eq!(encoder.message_len(), 1);
    assert_eq!(encoder.codeword_len(), 3);
    assert_eq!(encoder.information_positions(), &[2]);

    let message = [Bit::One];
    let word = encoder.encode(&message)?;
    assert_eq!(word, vec![Bit::One, Bit::One, Bit::One]);
    assert_eq!(encoder.extract_message(&word)?, message.to_vec());
    Ok(())
}
```

`?` завершает функцию с ошибкой, если предыдущая операция вернула `Err`; при `Ok` извлекает значение и продолжает выполнение.

## 3. Ошибки и порядок проверок

Существующие варианты `LdpcError` сохранить. Добавить:

| Вариант | Поля | Условие |
| --- | --- | --- |
| `InvalidEncoderRank` | `rank: usize, cols: usize` | `r == 0` или `r == n` |
| `MessageLengthMismatch` | `expected: usize, actual: usize` | `message.len() != k` |
| `InvalidCodeword` | `unsatisfied_checks: usize` | Слово нужной длины имеет ненулевой синдром |
| `LinearAlgebra` | `source: gf_linalg::LinalgError` | Ошибка проверяемой операции плотной матрицы |

`WordLengthMismatch { expected, actual }` уже существует: использовать его при неверной длине слова. `SizeOverflow` использовать при переполнении вычисления размеров новых буферов.

Сохранить `Debug`, `PartialEq`, `Eq`, `Display` и `std::error::Error`. Для `LinearAlgebra` добавить `From<gf_linalg::LinalgError>` и вернуть исходную ошибку из `Error::source()`. Это позволяет применять `?` к `Matrix::try_new` и `try_mul_vector`, сохраняя причину ошибки. Проверки не зависят от точного текста `Display`.

Порядок проверок:

1. **Конструктор:** проверенные размеры `H` → проверка размеров буферов → плотная матрица → один RREF → проверка `0 < r < n` → коэффициенты и отображение позиций → готовый кодер.
2. **Кодирование:** точная длина `k` → преобразование битов в вектор → вычисление проверочных битов → слово в исходном порядке.
3. **Извлечение:** точная длина `n` → синдром исходной `H` → отказ при ненулевом синдроме → выбор информационных битов.

Пустое сообщение — ошибка длины, поскольку `k > 0`. Для слова неверной длины не вычислять синдром и не возвращать `InvalidCodeword` вместо `WordLengthMismatch`. Число невыполненных проверок считать по всем исходным строкам, включая повторяющиеся.

Некорректный пользовательский ввод не должен вызывать панику, `todo!()` или частичный результат. Ошибки внутренних матричных операций передаются вызывающему коду, а не заменяются успешным нулевым словом. Для проверенного `H` и корректного кодера большинство таких ошибок недостижимы: отдельно проверять передачу `source`, но не создавать искусственный публичный способ нарушить инварианты.

## 4. Подготовка кодера

### 4.1. Плотная матрица над GF(2)

Внутренний помощник в `encoder.rs` преобразует `&ParityCheckMatrix` в `Result<Matrix<Gf2>, LdpcError>`:

1. Взять `m = checks.rows()` и `n = checks.cols()`.
2. Проверить `m.checked_mul(n)` и размер буфера в байтах через `checked_mul(size_of::<Gf2>())`.
3. Создать `m * n` нулей GF(2).
4. Через `check_bits(row)` проставить `Gf2::one()` по адресу `row * n + col`.
5. Вызвать `Matrix::<Gf2>::try_new(m, n, data)`.

Элементы идут по строкам. Пустые и повторяющиеся проверки сохраняются. Публичный метод преобразования разреженной матрицы в плотную не нужен: это деталь подготовки кодера. Чтение смежностей не меняет исходную матрицу.

### 4.2. Ранг и позиции

Вызвать `dense.rref()` ровно один раз и использовать `result.rank()`, `result.pivot_columns()` и `result.matrix()`. Не вызывать дополнительно `dense.rank()`: он сам запускает RREF и повторит работу.

Обозначения:

- `P = [p₀, ..., pᵣ₋₁]` — опорные столбцы;
- `I = [i₀, ..., iₖ₋₁]` — остальные столбцы, в порядке возрастания;
- `R` — приведённая матрица.

Если `r == 0` или `r == n`, вернуть `InvalidEncoderRank`. Нулевая и полноранговая матрицы остаются допустимыми объектами `ParityCheckMatrix`, но для выбранного контракта кодера не подходят. Ранги `1` и `n - 1` допустимы. Не требовать `m < n`: при зависимых строках подходящий код может иметь `m >= n`.

Опорная единица строки `a` находится в столбце `P[a]`. Ненулевые строки RREF — первые `r`; остальные `m - r` строк для расчёта коэффициентов не используются.

### 4.3. Систематическая форма и коэффициенты

Мысленно расположим столбцы в порядке `[I, P]`. Тогда RREF имеет вид:

```text
[ B | I_r ]
[ 0 |  0  ]
```

Здесь `I_r` — единичная матрица порядка `r`, а не список информационных позиций. `B` — матрица размера `r × k`, заданная `B[a, j] = R[a, I[j]]`.

Для сообщения `u` и проверочных битов `p` условие допустимости:

```text
B u + p = 0
p = -B u = B u, поскольку в GF(2) минус совпадает с плюсом.
```

Создать `Matrix<Gf2>` формы `r × k` с коэффициентами `B`. Проверить произведение размеров и число байтов перед выделением. Обе оси положительны и не превышают `MAX_MATRIX_DIM`.

Саму полную матрицу со столбцами `[I, P]` создавать не нужно: достаточно выбрать коэффициенты из `R` и построить отображения позиций. Не хранить плотные `H` и `R` после подготовки, не вычислять обратную матрицу и не выполнять Гаусс при каждом `encode`.

### 4.4. Отображение систематических позиций

Построить одно закрытое отображение длины `n`:

```text
systematic_to_original = I, затем P
```

`systematic_to_original[t]` — позиция в исходной `H`, куда помещается элемент с систематическим индексом `t`. Кодирование и извлечение используют это отображение напрямую; обратное отображение не требуется. Каждый индекс `0..n` встречается ровно один раз.

Отдельные копии `I` и `P` хранить не требуется: методы позиций возвращают срезы `systematic_to_original[..k]` и `systematic_to_original[k..]`. Длины вывести из `B`: `k = B.cols()`, `r = B.rows()`, `n = checks.cols()`.

Предлагаемые закрытые поля кодера:

```rust
checks: ParityCheckMatrix,
parity_coefficients: gf_linalg::Matrix<Gf2>, // B: r × k
systematic_to_original: Vec<usize>,
```

Инварианты: `r + k == n`, `systematic_to_original` является перестановкой позиций `0..n`, `B` согласована с позициями и исходной `H`. Все поля устанавливаются вместе конструктором и после создания не меняются.

## 5. Кодирование и извлечение

### 5.1. Кодирование

После проверки длины сообщения:

1. Получить `u = bits_to_vector(message)`.
2. Вычислить `p = parity_coefficients.try_mul_vector(&u)?`.
3. Преобразовать только `p` в биты через `vector_to_bits`.
4. Создать итоговый `Vec<Bit>` длины `n`, записать `message[j]` в `information_positions()[j]` и проверочные биты в `parity_positions()`.

Систематический порядок — внутренняя деталь; возвращаемое слово всегда соответствует столбцам исходной `H`. Не собирать промежуточное полное систематическое слово. Сохранить длину, порядок информационных битов, хвостовые нули и полностью нулевое сообщение. Кодер и входной срез не меняются; повторный вызов не зависит от предыдущего блока.

В обычном `encode` повторная проверка синдрома не нужна: допустимость обеспечивается подготовленными коэффициентами и проверяется тестами. Для одного блока умножение занимает `O(rk)`, перестановка — `O(n)`, временные данные — `O(n)`.

### 5.2. Извлечение сообщения

1. Проверить `word.len() == n`.
2. Вызвать `checks.syndrome(word)` по исходным разреженным проверкам.
3. Посчитать компоненты, равные `Bit::One`; при ненулевом числе вернуть `InvalidCodeword`.
4. Вернуть `word[systematic_to_original[t]]` для `t` из `0..k`.

Это проверяемое извлечение, а не исправление ошибок. Его стоимость — `O(m + E + k)`, где `E` — число единиц исходной `H`. Входное слово не меняется.

**Правило для чужого слова:** слово, допустимое для другой матрицы, но нарушающее текущую `H`, отклоняется. Если другое слово удовлетворяет текущей `H`, кодер принимает его и извлекает соответствующее сообщение. Принадлежность слова текущему коду не доказывает, что именно оно передавалось; эталонное сообщение этот API не получает.

## 6. Контрольные примеры

### 6.1. Матрица из общего плана: зависимая строка

Использовать уже приведённые в `GENERAL-PLAN.md` данные:

```text
H = [[1, 1, 0, 1, 0, 0],
     [0, 1, 1, 0, 1, 0],
     [1, 0, 0, 0, 1, 1],
     [0, 0, 1, 1, 0, 1]]

R = [[1, 0, 0, 0, 1, 1],
     [0, 1, 0, 1, 1, 1],
     [0, 0, 1, 1, 0, 1],
     [0, 0, 0, 0, 0, 0]]

r = 3, k = 3
P = [0, 1, 2], I = [3, 4, 5]
B = [[0, 1, 1],
     [1, 1, 1],
     [1, 0, 1]]

message = [0, 1, 1]
parity  = [0, 0, 1]
word    = [0, 0, 1, 0, 1, 1]
```

Четвёртая строка — XOR первых трёх. Поэтому длина сообщения равна 3, а не `n - m = 2`. Полностью перебрать все восемь сообщений и сравнить результаты с независимым синдромом и извлечением.

### 6.2. Перестановка с циклом длины три

В основном примере `systematic_to_original = [3, 4, 5, 0, 1, 2]`; его обратное отображение случайно совпадает с ним, поэтому он не выявляет ошибку чтения отображения в обратном направлении. Обязателен второй пример:

```text
H = [[1, 1, 0, 0, 1],
     [0, 0, 1, 1, 1]]

P = [0, 2], I = [1, 3, 4]
B = [[1, 0, 1],
     [0, 1, 1]]

systematic_to_original = [1, 3, 4, 0, 2]

message = [1, 0, 1]
parity  = [0, 1]
c_sys   = [1, 0, 1, 0, 1]
word    = [0, 1, 1, 0, 1]
```

Цикл `0 → 1 → 3 → 0` длины три выявляет ошибку направления: обратное отображение здесь было бы `[3, 0, 4, 1, 2]`, но кодер его не хранит. Проверить точное слово, информационные позиции и все восемь сообщений по направлению `systematic_to_original`. Для отдельной перестановки использовать `H = [[0, 1, 1]]`: свободные позиции `[0, 2]`, а `systematic_to_original = [0, 2, 1]`. Пример с тождественным отображением — `H = [[0, 0, 1]]`: свободные позиции `[0, 1]`, `systematic_to_original = [0, 1, 2]`.

## 7. Стратегия тестирования

Использовать стандартные `#[test]`, без новых зависимостей. Тесты поведения писать до операции или одновременно с ней. Частные помощники подготовки можно проверять модульными тестами в `encoder.rs`; внешний API — интеграционными тестами.

### Обязательные случаи

| Группа | Проверки |
| --- | --- |
| Плотная H | Порядок по строкам; крайние индексы; нулевые и повторяющиеся строки; источник не меняется |
| Подготовка | `k = n - r`; точные позиции; сохранение исходного порядка столбцов; повторная подготовка одинаковой H детерминирована |
| Зависимые проверки | Добавление нулевых, повторяющихся и линейно зависимых строк не меняет код, k и выдаваемые слова |
| Форма | Прямоугольные H; допустимая H с `m >= n`; столбец без единиц становится информационным |
| Ранги | Отказ для `r = 0` и `r = n`; успех для `r = 1` и `r = n - 1`; при `n = 1` кодер создать нельзя |
| Размеры | Отдельно H формы `1 × 4096` и `4096 × 2` с рангом 1; размеры выше лимита продолжает отклонять имеющийся конструктор H |
| Перестановки | Тождественное отображение, перестановка контрольного примера и цикл длины 3; отображение содержит каждую позицию `0..n` ровно один раз |
| Кодирование | Точное ожидаемое слово, систематичность, нулевой синдром, сохранение хвостовых нулей и нулевого сообщения |
| Длина сообщения | Пустое, короче k и длиннее k дают точный `MessageLengthMismatch` |
| Извлечение | Допустимое слово возвращает исходные k битов; неверная длина имеет приоритет перед синдромом |
| Недопустимое слово | При неверном проверочном бите возвращается `InvalidCodeword` с числом нарушенных исходных строк |
| Чужое слово | Недопустимое для текущей H отклоняется; другое допустимое слово принимается с соответствующим сообщением |
| Повторное использование | Несколько разных сообщений подряд дают те же результаты, что отдельные вызовы; входные данные сохраняются |
| Ошибки | Варианты и поля, форматирование, преобразование `LinalgError`, доступ к `source` |

При проверке границ использовать вытянутые матрицы, чтобы не запускать Гаусс на `4096 × 4096` в обычных тестах. `SizeOverflow` при действующих лимитах на целевых платформах недостижим через валидный публичный ввод; проверку переполнения всё равно сохранить и проверить при чтении кода.

### Независимые проверки маленьких кодов

1. Для двух контрольных матриц перебрать все `2^k` сообщений. Проверить длину `n`, информационные позиции, независимый плотный XOR-синдром и `extract_message(encode(u)) == u`.
2. Перебрать все `2^n` слов тех же матриц. Независимый синдром определяет допустимость; для каждого допустимого слова проверить `encode(extract_message(word)) == word`. Это проверяет и полноту кодера, и отказ для всех недопустимых слов.
3. Закодировать каждый базисный вектор сообщения: ровно один бит равен 1. Полученные слова образуют строки тестовой порождающей матрицы `G` размера `k × n` в исходном порядке столбцов. Через независимые XOR-суммы проверить `H Gᵀ = 0` и единичную подматрицу G на информационных позициях.
4. На маленьком примере проверить линейность: `encode(u XOR v) == encode(u) XOR encode(v)` для всех пар сообщений.

Эталонные вычисления не должны вызывать RREF, `encode` для расчёта ожидаемого синдрома или производственный помощник перестановки. G строится через кодер, но произведение с исходной H проверяется независимо. Верное извлечение само по себе недостаточно: одинаковая ошибка перестановки в обоих методах может скрыться в round-trip тесте.

## 10. Риски и ограничения

| Риск | Решение |
| --- | --- |
| Использование числа строк вместо ранга | Брать r из одного RREF; контрольный пример содержит зависимую строку |
| Перепутанное направление отображения | Зафиксированное значение `systematic_to_original`, точное кодовое слово и тест цикла длины 3; обратный массив не хранится |
| Сообщение извлекается из первых k позиций | Выбирать сохранённые свободные столбцы исходной H |
| Принимается слово с неверными проверочными битами | Вычислять синдром исходной H перед извлечением |
| Другое допустимое слово объявляется ошибкой передачи | Документировать, что без эталона такое различие определить нельзя |
| Round-trip скрывает общую ошибку двух методов | Точные слова, независимый синдром и перебор всех слов |
| Рост памяти и времени подготовки | Хранить только B и разреженную H, освободить плотные временные матрицы; не повторять RREF |

Разреженность H не означает разреженность B. Постоянная память кодера — `O(m + n + E + rk)`, подготовка требует `O(mn + rk + m + n + E)` памяти с учётом временных буферов и `O(mnr)` операций поля для текущего плотного RREF. При `4096 × 4096` временные массивы могут быть велики; числовой предел формы сохраняется, но гарантия малого расхода памяти и времени не вводится.

Проверка переполнения размера не равна обработке нехватки памяти. Сохраняется принятый в проекте подход к выделению `Vec`; отдельный fallible allocator API и ошибка OOM не вводятся.

Предел исходного сообщения 4096 байт из ТЗ относится к будущему байтовому слою. Здесь `k` измеряется в битах одного блока; предел 128 КиБ для полиномов к этому API не применяется, поскольку полиномы не создаются.
