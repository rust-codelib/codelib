# cascade-codes

Каскадные коды (cascade codes) — регенерирующие коды с точным восстановлением узлов для распределённого хранения. Реализация построена по статье M. Elyasi, S. Mohajer, «Cascade Codes For Distributed Storage Systems», [arXiv:1901.00911](https://arxiv.org/abs/1901.00911) (v2, 2020).

Rust 1.81+ · `std` · `unsafe` запрещён.

Файл из `F` символов поля распределяется по `n` узлам, каждый узел хранит `alpha` символов. Код обеспечивает два свойства:

- **восстановление данных**: любые `k` узлов позволяют восстановить весь файл;
- **точное восстановление узла**: содержимое отказавшего узла восстанавливается побитно по данным любых `d` других узлов, причём каждый помощник передаёт только `beta` символов — заметно меньше, чем при полном декодировании.

Параметр режима `mu ∈ 1..=k` выбирает точку компромисса между объёмом хранения и полосой восстановления: `mu = 1` даёт точку MBR (минимальная полоса), `mu = k` — точку MSR (минимальный объём).

## Быстрый старт

```toml
[dependencies]
cascade-codes = { path = "../codelib/cascade-codes" }
gf2m = { path = "../codelib/gf2m" }
```

```rust
use cascade_codes::{
    CascadeConfigurator, CascadeError, DataDecoder, DecodeStatus, Encoder, NodeRepairer,
};
use gf2m::Gf256;

fn main() -> Result<(), CascadeError> {
    // n = 8 узлов, любые k = 4 восстанавливают файл, d = 6 помощников, режим mu = 2.
    let code = CascadeConfigurator::new(8, 4, 6).mode(2).build::<Gf256>()?;
    let p = code.params();
    assert_eq!((p.alpha(), p.beta(), p.file_size()), (18, 5, 68));

    // Один блок из F символов -> содержимое всех n узлов.
    let message: Vec<Gf256> = (0..p.file_size()).map(|i| Gf256::new(i as u16)).collect();
    let nodes = code.encode(&message)?;

    // Восстановление данных из любых k узлов.
    let survivors = vec![nodes[7].clone(), nodes[2].clone(), nodes[5].clone(), nodes[0].clone()];
    let result = code.decode(&survivors, None)?;
    assert_eq!(result.status(), DecodeStatus::Consistent);
    assert_eq!(result.message(), &message[..]);

    // Точное восстановление узла 3: каждый из d помощников шлёт beta символов.
    let payloads = [0, 1, 2, 4, 5, 6]
        .iter()
        .map(|&h| code.repair_payload(&nodes[h], 3))
        .collect::<Result<Vec<_>, _>>()?;
    assert!(payloads.iter().all(|pl| pl.symbols.len() == 5));
    assert_eq!(code.repair(3, &payloads, None)?, nodes[3]);
    Ok(())
}
```

Байтовое сообщение кодируется так же просто:

```rust
use cascade_codes::{CascadeConfigurator, CascadeError};
use gfpm::Gf13;

fn main() -> Result<(), CascadeError> {
    let code = CascadeConfigurator::new(7, 3, 5).build::<Gf13>()?; // по умолчанию MSR
    let file = code.encode_bytes(b"hello, storage")?;
    let result = code.decode_bytes(file.byte_len, &file.shares[4..], None)?;
    assert_eq!(result.bytes(), b"hello, storage");
    Ok(())
}
```

## Параметры

Для системы `(n, k, d)` с `1 <= k <= d < n` и режима `mu ∈ 1..=k` теорема 1 статьи даёт:

| Величина | Формула | Смысл |
|---|---|---|
| `alpha` | `Σ_{m=0}^{mu} (d−k)^{mu−m} · C(k, m)` | символов хранит один узел |
| `beta` | `Σ_{m=0}^{mu} (d−k)^{mu−m} · C(k−1, m−1)` | символов передаёт один помощник |
| `F` | `Σ_{m=0}^{mu} k·(d−k)^{mu−m} · C(k, m) − C(k, mu+1)` | информационных символов в блоке |

Частные случаи (следствия 1 и 2): `mu = 1` — MBR с `(alpha, beta, F) = (d, 1, k(2d−k+1)/2)`; `mu = k` — MSR с `((d−k+1)^k, (d−k+1)^{k−1}, k(d−k+1)^k)`; `mu = k − 1` достигает границы разреза. Пример статьи `(8, 4, 6; 4)` даёт `(81, 27, 324)`.

[`CascadeParams::try_new`] проверяет параметры и вычисляет эти величины; [`CascadeParams::tradeoff`] перечисляет все точки компромисса для `(n, k, d)`. Построенная супер-матрица всегда сверяется с формулами: расхождение вернуло бы `CascadeError::Internal`.

Поле `F` должно иметь не меньше `n` элементов (`q >= n`): узлу `i` соответствует точка Вандермонда с номером `i`.

## Операции

| Задача | API |
|---|---|
| Проверить параметры, посмотреть компромисс | [`CascadeParams`], [`CascadeParams::tradeoff`] |
| Построить код | [`CascadeConfigurator`] (`mode`, `mbr`, `msr`, `decoder_config`, `build`), [`CascadeCode::try_new`] |
| Кодировать блок из `F` символов | [`Encoder::encode`], [`Encoder::encode_node`] |
| Восстановить блок по `>= k` узлам | [`DataDecoder::decode`], [`CascadeCode::decode_with`] |
| Восстановить отказавший узел | [`NodeRepairer::repair_payload`] (на помощнике), [`NodeRepairer::repair`] (на новом узле) |
| Работать с байтами (до 4096 байт) | [`CascadeCode::encode_bytes`], [`CascadeCode::decode_bytes`], [`CascadeCode::file_repair_payload`], [`CascadeCode::file_repair`] |
| Упаковать байты в символы и обратно | [`pack_bytes`], [`unpack_bytes`], [`bits_per_symbol`] |
| Получить матрицы `Ψ` и `M` | [`CascadeCode::encoder_matrix`], [`CascadeCode::message_matrix`] |
| Журналировать события | [`CascadeObserver`], [`CascadeEvent`], [`EventLog`] |

Трейты [`Encoder`], [`DataDecoder`] и [`NodeRepairer`] — фиксированные интерфейсы кодера, декодера и восстановления узла; [`CascadeCode`] реализует все три. Содержимое узла передаётся как [`NodeShare`] (номер узла и символы), пакет помощника — как [`RepairPayload`].

Поддерживаемые поля: любые `gf2m::Gf<N, POLY>` (характеристика 2) и `gfpm::Gf<P, M, POLY>` (любая характеристика). Для своего типа достаточно реализовать [`CodeField`] поверх `gf_linalg::FieldElement`.

## Байтовый слой

Сообщение до [`MAX_MESSAGE_BYTES`] = 4096 байт упаковывается в символы по `b = floor(log2 q)` бит (младшие биты байта первыми; в `Gf256` — ровно байт на символ), разбивается на блоки по `F` символов и дополняется нулями. Узел хранит блоки подряд — `stripes · alpha` символов, пакет помощника содержит `stripes · beta` символов. Длина сообщения в байтах не кодируется: её нужно сохранить отдельно (поле `EncodedFile::byte_len`) и передать в `decode_bytes`.

## Подсчёт ошибок и места ошибок

Код рассчитан на стирания (отказ узла), но декодер дополнительно проверяет согласованность:

1. первая попытка восстанавливает блок по первым `k` переданным узлам;
2. результат перекодируется и сравнивается со **всеми** переданными узлами; несовпавшие узлы — предполагаемые места ошибок ([`DecodeResult::suspect_nodes`]), число несовпавших символов — [`DecodeResult::mismatched_symbols`];
3. если расхождения есть, перебираются другие подмножества из `k` узлов (не больше [`DecoderConfig::max_subset_trials`], по умолчанию 256) до первого однозначного результата.

Статус [`DecodeStatus`]: `Consistent` — все узлы совпали; `Corrected` — совпало `a` узлов, не совпало `e`, и `a >= k + e` (другой файл не может совпасть с таким числом узлов, поскольку любые `k` узлов однозначно задают файл); `Inconsistent` — однозначного результата не найдено, возвращён лучший кандидат. Гарантированная локализация `e` испорченных узлов требует `s >= k + 2e` переданных узлов и достаточного бюджета перебора.

При ровно `k` узлах проверить можно только внутреннюю избыточность: при `mu < k` имеем `F < k·alpha`, и часть повреждений видна; в точке MSR `F = k·alpha`, и повреждение по `k` узлам не обнаружить.

## Журналирование

Передайте `Some(&mut observer)` в `decode`, `repair`, `decode_bytes` или `file_repair`. События ([`CascadeEvent`]) приходят синхронно: начало, восстановленные сегменты (снизу вверх по дереву), проверенные подмножества с числом согласных узлов, итог; для восстановления узла — сегменты с числом символов на помощника и итоговый объём скачанного. [`EventLog`] сохраняет события как строки. При ошибке входа события не отправляются.

## Краткое описание реализации

1. **Супер-матрица сообщения** `M` (`d × alpha`) — конкатенация сообщений знаковых детерминантных кодов разных режимов (сегментов). Сегменты образуют дерево (алгоритм 1, раздел V): корень — код режима `mu` с нулевой подписью; ребёнок родителя `P` соответствует паре инъекции `(x, B)` с `B ⊆ [k+1 : d]`, `|B| < mode(P)`, `x ∈ [k+1 : d]`, `x <= max B` (замечание 5), его режим `mode(P) − |B| − 1` (11), подпись — по (12). Дерево обходится в ширину.
2. **Шаблон.** Каждый элемент `M` хранится символически: исходная часть (сырой символ `v`/`w`, ноль группы `G2`, либо проверочный символ, выраженный через сырые символы своей w-группы по (5)) плюс необязательная инъекция знаковой копии символа родителя (14). Шаблон строится один раз, не зависит от поля и от `n`.
3. **Кодирование**: `M` вычисляется по шаблону, узел `i` хранит `Ψ[i, :] · M`, где `Ψ` — матрица Вандермонда `n × d`.
4. **Восстановление данных** (алгоритм 2, раздел VII): `Γ[K,:]^{-1}` применяется к данным `k` узлов, сегменты обходятся от режима 0 к корню, столбцы — в обратном лексикографическом порядке; нижние строки столбца восстанавливаются из детей (`G1`), нулей (`G2`) или уравнения (5) с инъекцией соседа (`G3`), верхние — по (53). Инъецированные символы извлекаются из верхних проверочных символов вычитанием исходной части.
5. **Восстановление узла** (раздел VI): помощник умножает каждый свой сегмент на `Ξ^{f,(m)}` (7); новый узел получает `R_f(Q)` по (22) и собирает содержимое по (23), вычитая вклад инъекций через пространство восстановления родителя.

## Детали реализации

- **Нумерация с нуля.** Строки и элементы множеств статьи `1..=d` внутри крейта — `0..d`; верхние `k` строк — `0..k`. Функция `ind_I(x)` и знаки от сдвига не зависят. Узлы нумеруются `0..n`.
- **Знаки** `(−1)^σ` хранятся как чётность. В характеристике 2 отрицание тождественно, и все знаки исчезают (замечание 4); тесты гоняются и над `GF(2^8)`, и над `GF(13)`, `GF(9)`, `GF(251)`.
- **Группа `G2`** обнуляется только в нижних `d − k` строках (определение 8). В строке 26 псевдокода алгоритма 1 условие обнуления записано без `x > k`; такая версия обнулила бы и верхние элементы (например, `T2[1, {5,6}] = w1,{1,5,6}`, который в матрице (16) статьи ненулевой) и дала бы меньше `F` символов. Реализация следует определению 8 и матрице (16) — число информационных символов совпадает с формулой (3).
- **Порядок информационных символов в блоке**: по сегментам в порядке обхода дерева, внутри сегмента — по столбцам в лексикографическом порядке, внутри столбца — по строкам. Позиции сегментов в `M` идут в том же порядке; [`CascadeCode::segment_modes`] возвращает их режимы. Порядок детей одного родителя: по `|B|`, затем `B` лексикографически, затем `x` (в статье порядок детей не фиксирован).
- **Полоса `beta`.** Помощник вычисляет `y = u · Ξ` и передаёт только координаты в опорных столбцах RREF(`Ξ`); новый узел восстанавливает `y` как комбинацию ненулевых строк RREF. Сумма рангов по сегментам сверяется с `beta` из (3). Пакет помощника зависит только от него и от отказавшего узла.
- **Проверочные символы при декодировании** вычисляются через уже восстановленные сырые символы w-группы — это то же уравнение (5), что и в алгоритме 2.
- Используется `gf_linalg::Matrix` для обращения `Γ[K,:]`, `Ψ[H,:]` и для RREF матриц `Ξ`.
- **Перебор подмножеств** при поиске испорченных узлов ленивый: подмножества порождаются по одному, поэтому бюджет `max_subset_trials` ограничивает и время, и память при любом числе переданных узлов.

## Ограничения

- `n <= 4096` ([`MAX_NODES`]) и `alpha <= 4096` ([`MAX_ALPHA`]): супер-матрица и матрицы `Ξ` не выходят за предел осей `gf-linalg`. Ширина `C(d, m)` каждой нужной таблицы подмножеств также ограничена 4096. При больших `k` и `d − k` предел `alpha` быстро достигается: например, `(n, 12, 30; 12)` недопустим.
- `q >= n`. Матрица кодера — только Вандермонда; произвольная матрица с условиями (E1), (E2) и полусистематическая форма (приложение C) не поддерживаются, поэтому код не систематический: данные не лежат в узлах в открытом виде.
- Байтовое сообщение — до 4096 байт; длину в байтах хранит вызывающий код.
- Код исправляет стирания. Поиск испорченных узлов — перебор подмножеств с ограниченным бюджетом; он не является декодером ошибок с гарантией при `s < k + 2e`.
- Самостоятельного типа многочлена в workspace пока нет, поэтому преобразование «сообщение ↔ многочлен» представлено упаковкой байтов в вектор символов поля.
- Производительность не оптимизировалась: декодирование — `O(k · d · alpha)` плюс перекодирование для проверки; восстановление узла строит и приводит матрицы `Ξ` при каждом вызове.
