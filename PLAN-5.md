**Статус:** задачи 5.1–5.3 выполнены, прошли ревью и приёмочные проверки; каждая задача зафиксирована отдельным коммитом по запросу пользователя.

## Объём и решения

Завершить приёмку существующего битового API, без изменения публичных сигнатур. `Encoder`, `Decoder`, конфигуратор, преобразования вектора, диагностика и события уже реализованы. Тесты `encoder_algebra.rs` перебирают пространство маленьких кодов и проверяют линейность кодера; новые проверки должны охватить весь кодек, не дублируя этот файл.

Использовать существующий workspace `proptest` как dev-зависимость `ldpc-codes`: он уже применяется для полей. Проверки ограничить маленькими матрицами и сообщениями, чтобы не раздувать время CI. Для генерируемых матриц гарантировать `0 < rank(H) < n` конструкцией, без массового отбрасывания случаев и без собственного генератора случайных чисел. Синдром проверять независимым плотным XOR-расчётом.

README крейта должен быть кратким пользовательским руководством: назначение, Rust/std, локальная зависимость, быстрый старт, таблица операций, LLR/стирания, вектор, диагностика/события, ограничения, примеры и проверки. Ссылки на публичные типы должны работать в rustdoc (`lib.rs` включает README). Не превращать README в перечень этапов разработки или копию всей спецификации.

Этап 6, общий тип полинома, байтовая упаковка, канальная модель, Min-sum и оптимизации не входят в работу. Первая битовая версия не означает выполнение всего ТЗ. Изменения арифметики полей, `gf-linalg` и контрактов Рида–Соломона не требуются.

## Задачи

### 5.1. Проверить свойства всего кодека

- [x] Перебрать все сообщения небольшого кода через конфигуратор, векторные преобразования, кодирование, безошибочные LLR, декодирование и извлечение. Проверить слово, длины, нулевой синдром по независимой H, `ParitySatisfied`, 0 итераций, нулевые изменения и реальные ошибки, сохранение нулевого сообщения/хвостовых нулей.
- [x] Добавить property-тесты на семействе небольших допустимых матриц и сообщениях: линейность кодирования, нулевой синдром, безошибочный round-trip; предусмотреть информационные позиции вне начала слова, изолированные столбцы, зависимые и пустые строки. Использовать повторные блоки с одним декодером там, где это проверяет независимость входов.
- [x] Дополнить семейство кодека случайными перестановками столбцов: проверять сохранение ранга, информационную позицию перемещённого нулевого столбца, кодирование и синдром в порядке переставленной матрицы.
- [x] Генерировать графы с 1–5 проверками и 1–7 битами, LLR от `-10.0` до `10.0` с шагом `0.1`, и выполнять один-два реальных шага SPA против независимого `DirectReference`. В property-тесте предел канальных LLR и сообщений `q` равен `5.0`; поэтому `|tanh(q / 2)| ≤ tanh(2.5) ≈ 0.9867`, а произведение до шести множителей при максимальной степени проверки 7 остаётся не ближе `0.922` к единице. Это ограничивает чувствительность `atanh` к округлению. Для численных сравнений использовать абсолютный допуск `2e-9` и относительный `2e-10`; при posterior около нуля проверять правило hard decision каждого результата, а сравнивать решения и синдромы алгоритмов только там, где они однозначны. Синдром SPA при этом сверять с плотным XOR для всех строк.
- [x] Пройти `cargo test -p ldpc-codes --test codec_properties`, `cargo test -p ldpc-codes`, `cargo test -p ldpc-codes --release`, fmt и Clippy пакета.

Новые свойства дополнительно проверены с `PROPTEST_CASES=1000` для перестановок столбцов и генерируемых шагов SPA в debug и release. Размеры матриц и диапазон LLR остаются небольшими; от случайного шумного входа не требуется успешное декодирование.

Файлы: `ldpc-codes/tests/codec_properties.rs`, `ldpc-codes/Cargo.toml`, `Cargo.lock` только если cargo действительно изменит запись зависимостей пакета. Зависимости: этапы 0–4. Размер: средний. После ревью — отдельный коммит.
