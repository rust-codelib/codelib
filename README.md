# codelib

Учебный Rust workspace для арифметики конечных полей, полиномов, линейной алгебры и кодов исправления ошибок. Проект состоит из библиотечных крейтов без GUI.

## Двоичные LDPC-коды

Крейт [`ldpc-codes`](ldpc-codes/README.md) предоставляет `Bit`, преобразования битов и `gf_linalg::Vector<Gf2>`, разреженную проверочную матрицу с доступом к смежностям, синдром, проверку `is_codeword` и систематический кодер `SystematicEncoder`. Кодер использует ранг `H`, допускает зависимые строки и принимает ровно `k = n - rank(H)` битов; слово возвращается в порядке столбцов исходной `H`. Для вызова методов `encode` и `extract_message` импортируйте trait `Encoder`. Извлечение проверяет длину и синдром, но нулевой синдром подтверждает только допустимость слова и не доказывает, что именно это слово было передано.

Каждая ось матрицы ограничена диапазоном `1..=4096`; пустые и повторяющиеся строки допустимы. Запустить пример кодирования и извлечения можно командой `cargo run -p ldpc-codes --example systematic_encode`. SPA-декодер и связь с общим типом многочлена пока не реализованы.

## Согласованные ограничения размеров

| Объект | Ограничение |
| --- | --- |
| Матрица | До 4096 строк и 4096 столбцов включительно; предел применяется отдельно к каждой оси |
| Вектор | Без отдельного ограничения числа элементов |
| Массив коэффициентов `gf-linalg` | Не более 128 КиБ (131 072 байта) для элементов одного массива; число элементов зависит от размера `F` |
| Исходное сообщение | До 4096 байт включительно |
| Кодовое слово | Ограничения выбранного алгоритма кодирования и поля |

Длина вектора не ограничивается ни размером матрицы, ни объёмом полинома. При умножении матрицы на вектор проверяется совпадение длины вектора с числом столбцов матрицы. Число элементов матрицы должно точно соответствовать произведению числа строк и столбцов; переполнение при вычислении этого произведения проверяется отдельно.

В `gf-linalg` предел 128 КиБ считается только по длине массива коэффициентов и размеру элемента поля `F` (`len * size_of::<F>()`). В него не входят метаданные `Box`, накладные расходы аллокатора, внешний список строк и его ёмкость. Например, `Gf256` занимает 2 байта и допускает до 65 536 коэффициентов. Для матрицы предел применяется к каждой строке отдельно; общего предела на сумму строк нет, поэтому их суммарный объём может быть больше 128 КиБ. Эти преобразования работают с массивами коэффициентов; отдельного типа многочлена и арифметики над ним пока нет.

## Преобразования и кодирование

- При преобразовании вектора в массив коэффициентов проверяется объём массива. Превышение предела возвращается как ошибка преобразования; такой вектор остаётся допустимым вектором.
- При преобразовании массива коэффициентов в вектор отдельного предела длины нет.
- Матрица представляется массивами коэффициентов по строкам. При таком преобразовании размер проверяется для каждой строки отдельно; предел одного массива не ограничивает объём всей матрицы.
- Размер коэффициентов в памяти зависит от представления элемента поля, поэтому допустимое число коэффициентов может различаться для разных типов полей.
- Предел 4096 байт относится к исходному сообщению до кодирования и восстановленному сообщению после декодирования. Проверочные символы могут увеличивать размер закодированных данных.
- Длина блока и параметры кода проверяются по требованиям алгоритма.
  При необходимости исходное сообщение разбивается на блоки.

## Внутренние вычисления

Алгоритмы могут использовать векторы, срезы и отдельные рабочие буферы для промежуточных данных. Например, при обращении матрицы дополненную таблицу `[A | I]` можно хранить в рабочем буфере либо обрабатывать две матрицы отдельно. Каждый объект `Matrix` сохраняет установленный предел размеров.

Максимум матрицы следует задавать одной константой; алгоритмы должны использовать фактические размеры данных. Это позволит пересмотреть предел позже, сохранив проверки формы и переполнения.

## Статус линейной алгебры

Этапы 1–6 линейной алгебры реализованы в пакете [`gf-linalg`](gf-linalg/README.md); отдельно выполнен этап 0 подготовки к LDPC — RREF и вычисление ранга. `Vector<F>` и прямоугольный `Matrix<F>` работают с обоими статическими семействами полей: `gf2m::Gf<N, POLY>` и `gfpm::Gf<P, M, POLY>`, если параметры задают поле. Для пользовательского типа достаточно арифметического контракта `FieldElement`; для текстового формата отдельно реализуется `FieldText`. По умолчанию параметром `F` остаётся `Gf256`.

Матрица проверяет размеры и число элементов, а доступ к строкам и элементам безопасно обрабатывает выход за границы. Для векторов доступны сложение, вычитание, умножение на скаляр и сравнение; скалярное произведение пока возвращает явную ошибку «не реализовано». Для матриц доступны сложение, вычитание, произведение матриц, транспонирование, сравнение, умножение на вектор, RREF с индексами опорных столбцов и вычисление ранга. RREF и ранг работают над прямоугольными и вырожденными матрицами, сохраняют порядок столбцов и не меняют источник. Определитель и обратная матрица доступны только для квадратной матрицы: определитель вырожденной матрицы равен нулю, а обращение возвращает `LinalgError::SingularMatrix`. Операции проверяют совместимость размеров и возвращают `LinalgError`, если выполнить их нельзя.

Для `Vector<F>` и `Matrix<F>` доступны текстовые `Display`/`FromStr`, если поле поддерживает `FieldText`, и преобразования в массивы коэффициентов с сохранением длины и хвостовых нулей. Самостоятельный тип многочлена и арифметика над ним пока не реализованы.
