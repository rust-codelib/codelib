# codelib

Учебный Rust workspace для арифметики конечных полей, полиномов, линейной алгебры и кодов исправления ошибок. Проект состоит из библиотечных крейтов без GUI.

## Согласованные ограничения размеров

| Объект | Ограничение |
| --- | --- |
| Матрица | До 4096 строк и 4096 столбцов включительно; предел применяется отдельно к каждой оси |
| Вектор | Без отдельного ограничения числа элементов |
| Массив коэффициентов `gf-linalg` | Не более 128 КиБ (131 072 байта) для массива элементов; с `Gf256` — до 65 536 коэффициентов |
| Исходное сообщение | До 4096 байт включительно |
| Кодовое слово | Ограничения выбранного алгоритма кодирования и поля |

Длина вектора не ограничивается ни размером матрицы, ни объёмом полинома. При умножении матрицы на вектор проверяется совпадение длины вектора с числом столбцов матрицы. Число элементов матрицы должно точно соответствовать произведению числа строк и столбцов; переполнение при вычислении этого произведения проверяется отдельно.

В `gf-linalg` предел 128 КиБ считается только по длине массива коэффициентов и размеру его элементов (`len * size_of::<Gf256>()`). В него не входят метаданные `Box`, накладные расходы аллокатора, внешний список строк и его ёмкость. `Gf256` сейчас занимает 2 байта. Для матрицы предел применяется к каждой строке отдельно; суммарный объём всех строк может быть больше 128 КиБ. Эти преобразования пока используют массивы коэффициентов, отдельного типа многочлена над `Gf256` нет.

## Преобразования и кодирование

- При преобразовании вектора в полином проверяется объём массива коэффициентов. Превышение предела возвращается как ошибка преобразования; такой вектор остаётся допустимым вектором.
- При преобразовании полинома в вектор отдельного предела длины нет.
- Матрица представляется набором полиномов по строкам. При таком преобразовании размер проверяется для каждой строки отдельно; предел одного полинома не ограничивает объём всей матрицы.
- Размер коэффициентов в памяти зависит от представления элемента поля, поэтому допустимое число коэффициентов может различаться для разных типов полей.
- Предел 4096 байт относится к исходному сообщению до кодирования и восстановленному сообщению после декодирования. Проверочные символы могут увеличивать размер закодированных данных.
- Длина блока и параметры кода проверяются по требованиям алгоритма.
  При необходимости исходное сообщение разбивается на блоки.

## Внутренние вычисления

Алгоритмы могут использовать векторы, срезы и отдельные рабочие буферы для промежуточных данных. Например, при обращении матрицы дополненную таблицу `[A | I]` можно хранить в рабочем буфере либо обрабатывать две матрицы отдельно. Каждый объект `Matrix` сохраняет установленный предел размеров.

Максимум матрицы следует задавать одной константой; алгоритмы должны использовать фактические размеры данных. Это позволит пересмотреть предел позже, сохранив проверки формы и переполнения.

## Статус линейной алгебры

Этапы 1–5 линейной алгебры реализованы в пакете [`gf-linalg`](gf-linalg/README.md). `Vector` и прямоугольный `Matrix` работают над `Gf256`; матрица проверяет размеры и число элементов, а доступ к строкам и элементам безопасно обрабатывает выход за границы. Для векторов доступны сложение, умножение на скаляр и сравнение; скалярное произведение пока возвращает явную ошибку «не реализовано». Для матриц доступны сложение, произведение матриц, транспонирование, сравнение, умножение на вектор, вычисление определителя и обращение квадратной матрицы. Определитель и обратная матрица доступны только для квадратной матрицы: определитель вырожденной матрицы равен нулю, а обращение возвращает `LinalgError::SingularMatrix`. Операции проверяют совместимость размеров и возвращают `LinalgError`, если выполнить их нельзя.

Для `Vector` и `Matrix` реализованы текстовые `Display`/`FromStr` и преобразования в массивы коэффициентов с сохранением длины и хвостовых нулей. Самостоятельный тип многочлена и арифметика над ним пока не реализованы. Типы пока работают только с `Gf256`; обобщение по типу поля запланировано на этап 6.
