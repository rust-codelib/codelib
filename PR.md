# Добавить библиотеку двоичных LDPC-кодов с систематическим кодером и SPA-декодером

Ветка `iraedeus/ldpc-code` добавляет в `iraedeus/gf-linalg-ext` библиотечный крейт `ldpc-codes`. По заданной проверочной матрице `H` пользователь может кодировать блок информационных битов, декодировать принятые мягкие значения LLR и извлекать сообщение из допустимого кодового слова.

## Что реализовано

- Тип `Bit` и преобразования битов в `Vector<Gf2>` и обратно с сохранением длины и хвостовых нулей.
- Разреженная `ParityCheckMatrix` с проверкой размеров и индексов, смежностями со стороны строк и столбцов, вычислением синдрома и проверкой допустимости слова. Поддерживаются пустые и зависимые строки, а также изолированные столбцы.
- `SystematicEncoder`, использующий существующий RREF из `gf-linalg`. Длина сообщения определяется рангом `H`; информационные и проверочные биты размещаются в исходном порядке столбцов. Извлечение сообщения проверяет длину и синдром.
- Полный `SpaDecoder` и отдельный `spa_step`: разреженные сообщения, flooding-итерации, насыщение LLR, поддержка стираний, начальная проверка синдрома и остановка при успехе либо исчерпании бюджета.
- `LdpcConfigurator`, создающий согласованную пару кодера и декодера. Метод `ConfiguredLdpc::decode` сохраняет эту согласованность; матрица при сборке пары не клонируется.
- Публичные контракты `Encoder` и `Decoder`, проверяемый конструктор `DecodeResult::try_new`, статусы остановки, счётчики и синхронные события через `DecodeObserver`. Внешние реализации декодера могут создавать собственные результаты.
- Переиспользование рабочих буферов декодера и вычисление промежуточной диагностики только при наличии наблюдателя. Граф, состояние и численное ядро SPA разделены по модулям.
- README крейта, обновление корневого README и пять примеров: синдром, кодирование, один шаг SPA, журнал событий и полный цикл восстановления сообщения. Файлы рабочих планов исключены из репозитория.

Крейт использует существующие `gfpm` и `gf-linalg`; единственная зависимость для property-тестов — уже используемый в workspace `proptest`. Арифметика полей и контракты `rs-codes` не меняются.

## Проверки

Тесты включают полный перебор малых кодов, линейность кодирования, независимый плотный XOR-синдром, равенство `H Gᵀ = 0`, перестановки столбцов, сравнение шагов SPA с независимым численным эталоном, ошибки входа, события, повторное использование декодера и независимое владение результатом. Генерируемые шаги SPA проверены по 1000 случаев в debug и release; для сравнения около нуля явно задан численный допуск, граничные случаи сохранены как regression seeds.

Успешно выполнены:

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --offline -- -D warnings
cargo test --workspace --offline
cargo test --workspace --release --offline
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --offline
cargo +1.81.0 check --workspace --lib --offline
```

Все пять примеров `ldpc-codes` запускаются успешно.

## Границы первой версии

Крейт требует `std` и работает с одним блоком битов. Размер каждой оси `H` — от 1 до 4096; кодеру и конфигуратору нужен ранг `0 < rank(H) < n`. SPA может не сойтись или найти другое допустимое слово: нулевой синдром не доказывает совпадение с переданным сообщением, а `changed_bits` не означает число исправленных ошибок. Для точного сравнения с эталоном предусмотрен `count_bit_errors`.

Общий тип полинома и интеграция с ним, байтовая упаковка, модель канала и другие алгоритмы декодирования остаются вне этой версии.
